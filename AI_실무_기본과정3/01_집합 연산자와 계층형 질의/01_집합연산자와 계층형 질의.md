# SQL 집합 연산자와 계층형 질의

---

## STANDARD SQL

관계형 데이터베이스에서 원하는 정보를 도출하기 위한 기본적인 연산 집합으로, **합연산**과 **순수 관계 연산**으로 나뉩니다.

---

## 일반 집합 연산

- **합집합 (UNION)**: 두 릴레이션의 모든 튜플을 합치고 **중복을 제거**합니다. `UNION` 키워드를 사용합니다.

- **교집합 (INTERSECT)**: 두 릴레이션에 공통으로 존재하는 튜플만 추출하고 **중복을 제거**합니다. `INTERSECT` 키워드를 사용합니다. *(MySQL에서는 지원되지 않음)*

- **차집합 (EXCEPT 또는 MINUS)**: 한 릴레이션에서 다른 릴레이션에 있는 튜플을 제외한 나머지 튜플을 추출하고 **중복을 제거**합니다. `EXCEPT` 또는 `MINUS` 키워드를 사용합니다. *(MySQL에서는 지원되지 않음, MariaDB 10.3+에서 `EXCEPT` 지원)*

- **카티션 프로덕트 (CROSS JOIN)**: 두 릴레이션의 **모든 튜플을 서로 맵핑**하여 가능한 모든 조합을 만듭니다. `CROSS JOIN` 키워드를 사용합니다.

---

## 순수 관계 연산

- **셀렉션 (σ)**: 릴레이션에서 특정 조건을 만족하는 튜플(행)을 선택합니다. SQL의 `WHERE` 절에 해당합니다.

- **프로젝션 (π)**: 릴레이션에서 특정 속성(열)만 추출합니다. SQL의 `SELECT` 절에 해당합니다.

- **조인 (⋈)**: 두 개 이상의 릴레이션을 **공통 속성을 기반으로 연결**하여 새로운 릴레이션을 만듭니다. 세타 조인, 동등 조인, 자연 조인, 외부 조인 등 다양한 종류가 있습니다.

- **디비전 (÷)**: 한 릴레이션에 있는 튜플이 다른 릴레이션의 **모든 튜플과 관련되어 있는** 튜플을 찾는 연산입니다. *(SQL에서 직접적인 `DIVIDE BY` 키워드는 제공되지 않으며, 복잡한 쿼리로 구현해야 함)*

### 🔍쉬운설명

SQL에서 데이터를 다루는 방법은 크게 두 가지로 나눌 수 있어요.

**일반 집합 연산**: 마치 수학에서 집합을 다루는 것과 같아요.

- **합집합 (UNION)**: 두 개의 테이블에서 나온 결과들을 하나로 합치는 거예요. 중복되는 데이터는 한 번만 보여줘요. 예를 들어, 반 학생 명단 A와 반 학생 명단 B를 합칠 때, 이름이 겹치는 학생은 한 번만 나오게 하는 것과 같아요.

- **교집합 (INTERSECT)**: 두 테이블에 모두 존재하는 데이터만 뽑아내는 거예요. 반 학생 명단 A와 반 학생 명단 B에 동시에 있는 학생들만 보여주는 것과 같죠.

- **차집합 (EXCEPT/MINUS)**: 첫 번째 테이블에는 있지만, 두 번째 테이블에는 없는 데이터만 뽑아내는 거예요. 반 학생 명단 A에는 있지만, 반 학생 명단 B에는 없는 학생들만 보여주는 거죠.

- **카티션 프로덕트 (CROSS JOIN)**: 두 테이블의 모든 행을 서로 짝지어 연결하는 거예요. 예를 들어, 셔츠 색상(빨강, 파랑)과 바지 색상(검정, 흰색)이 있다면, 가능한 모든 조합(빨강+검정, 빨강+흰색, 파랑+검정, 파랑+흰색)을 만들어내는 것과 같아요. 매우 많은 결과가 나올 수 있으니 조심해야 해요!

**순수 관계 연산**: 특정 조건에 따라 데이터를 필터링하거나, 필요한 열만 선택하거나, 여러 테이블을 연결하는 기본적인 연산이에요.

- **셀렉션 (SELECT)**: 테이블에서 원하는 행을 고르는 거예요. `WHERE` 절을 사용해서 "나이가 20살 이상인 사람만 보여줘"처럼 조건을 걸 수 있어요.

- **프로젝션 (PROJECT)**: 테이블에서 원하는 열을 고르는 거예요. `SELECT` 절을 사용해서 "이름과 전화번호만 보여줘"처럼 특정 정보만 볼 수 있어요.

- **조인 (JOIN)**: 여러 테이블을 연결해서 한 번에 보는 거예요. 예를 들어, 학생 테이블과 성적 테이블을 연결해서 "각 학생의 이름과 성적을 함께 보여줘"라고 할 수 있죠. `CROSS JOIN`은 조인 중 하나지만, 조건 없이 모든 경우의 수를 연결한다는 점에서 특별해요.

- **디비전 (DIVIDE)**: 좀 더 복잡한 연산인데, "이 물건을 판매하는 모든 상점의 목록을 보여줘"와 같이, 특정 기준을 **모두 만족하는** 데이터를 찾을 때 사용해요. SQL에서는 이 연산을 직접적으로 지원하는 키워드는 없지만, 여러 SQL 문을 조합해서 구현할 수 있어요.

---

## 집합 연산자

두 개 이상의 테이블에서 `JOIN`을 사용하지 않고 연관된 데이터를 조회하는 방법 중 하나입니다. 집합 연산자를 사용하려면 **`SELECT`한 컬럼의 수**와 **각 컬럼의 데이터 타입**이 테이블 간 상호 호환 가능해야 합니다.

---

### UNION

두 테이블의 결과를 합치며 **중복된 데이터를 제거**합니다. 관계형 대수의 합집합 역할을 합니다. 내부적으로 정렬 과정을 통해 중복을 제거하며, 올바른 정렬을 위해서는 `ORDER BY` 구문을 명시적으로 사용해야 합니다.



# SQL UNION 연산 가이드

`UNION` 연산은 두 개의 테이블(`ALPHA`, `BETA`)에 있는 데이터를 하나로 합치는 연산입니다. 이 과정에서 **중복된 데이터를 자동으로 제거하고 정렬을 수행**합니다.

---

## 1. 입력 데이터 테이블

### ALPHA 테이블

| A | B | C |
| --- | --- | --- |
| A1 | B1 | 1 |
| A2 | B2 | 2 |
| A3 | B3 | 3 |

### BETA 테이블

| A | B | C |
| --- | --- | --- |
| <span class="beta-data">A1</span> | <span class="beta-data">B1</span> | <span class="beta-data">1</span> |
| <span class="beta-data">A4</span> | <span class="beta-data">B4</span> | <span class="beta-data">4</span> |

---

## 2. 연산 과정

1. **데이터 연결:** `ALPHA` 테이블과 `BETA` 테이블의 모든 행을 하나의 집합으로 합칩니다.
2. **정렬 및 중복 제거:** 합쳐진 데이터셋 내에서 동일한 값을 가진 행을 식별하고 제거합니다. *(예: `A1, B1, 1`이 중복됨)*
3. **최종 결과 도출:** 중복된 행을 하나만 남기고 정렬된 상태로 출력합니다.

---

## 3. 결과 테이블

| A | B | C |
| --- | --- | --- |
| A1 | B1 | 1 |
| A2 | B2 | 2 |
| A3 | B3 | 3 |
| <span class="beta-data">A4</span> | <span class="beta-data">B4</span> | <span class="beta-data">4</span> |

---

## 4. SQL 실행 코드

```sql
SELECT * FROM ALPHA
UNION
SELECT * FROM BETA;

```

---

### UNION ALL

`UNION`과 거의 같은 기능을 수행하지만, **중복 제거와 정렬을 하지 않습니다**. 중복 제거를 하지 않는 것이 가장 큰 차이점입니다.


# SQL UNION ALL 연산 가이드

`UNION ALL`은 두 테이블의 데이터를 단순히 결합하는 연산자로, `UNION`과 달리 **중복 제거와 정렬 과정을 생략하여 처리 속도가 빠릅니다.**

---

## 1. 입력 데이터 테이블

### ALPHA 테이블
| A | B | C |
| --- | --- | --- |
| A1 | B1 | 1 |
| A2 | B2 | 2 |
| A3 | B3 | 3 |

### BETA 테이블
| A | B | C |
| --- | --- | --- |
| <span class="beta-data">A1</span> | <span class="beta-data">B1</span> | <span class="beta-data">1</span> |
| <span class="beta-data">A4</span> | <span class="beta-data">B4</span> | <span class="beta-data">4</span> |

---

## 2. 연산 과정 (데이터 연결)

1. **단순 병합:** `ALPHA` 테이블의 모든 행 아래에 `BETA` 테이블의 모든 행을 순서대로 이어 붙입니다.
2. **정렬 및 중복 제거 생략:** `UNION`과 다르게 내부적인 정렬이나 중복 검사를 수행하지 않으므로, 데이터가 중복되어 존재하더라도 모두 결과에 포함합니다.

---

## 3. 결과 테이블

| A | B | C | 비고 |
| --- | --- | --- | --- |
| A1 | B1 | 1 | ALPHA 원본 |
| A2 | B2 | 2 | ALPHA 원본 |
| A3 | B3 | 3 | ALPHA 원본 |
| <span class="beta-data">A1</span> | <span class="beta-data">B1</span> | <span class="beta-data">1</span> | **중복 허용 (BETA 유래)** |
| <span class="beta-data">A4</span> | <span class="beta-data">B4</span> | <span class="beta-data">4</span> | **BETA 원본** |

---

## 4. SQL 실행 코드

```sql
SELECT * FROM ALPHA
UNION ALL
SELECT * FROM BETA;

```

---

### INTERSECT

두 테이블에 대해 **겹치는 부분을 추출**하며, 추출 후에는 중복된 결과를 제거합니다. 관계형 대수의 교집합 역할을 합니다. Oracle/MariaDB에서는 지원되지만 **MySQL에서는 지원되지 않으므로**, `JOIN` 등을 활용해야 합니다.

```sql
SELECT A, B FROM ALPHA
INTERSECT
SELECT A, B FROM BETA;
```




# SQL INTERSECT 연산 가이드

`INTERSECT` 연산자는 두 테이블(`ALPHA`, `BETA`)에서 지정한 컬럼을 기준으로 **공통으로 존재하는 데이터(교집합)만을 추출**하며, 최종 결과에서 중복을 제거합니다.

---

## 1. 입력 데이터 테이블

### ALPHA 테이블
| A | B | C |
| --- | --- | --- |
| <span class="beta-data">A1</span> | <span class="beta-data">B1</span> | 1 |
| A2 | B3 | 2 |
| A3 | B4 | 4 |

### BETA 테이블
| A | B | C |
| --- | --- | --- |
| <span class="beta-data">A1</span> | <span class="beta-data">B1</span> | 1 |
| <span class="beta-data">A1</span> | <span class="beta-data">B1</span> | 3 |

---

## 2. 연산 과정

1. **겹치는 부분 추출 (컬럼 A, B 기준):** `SELECT A, B`를 수행하므로 C 컬럼은 제외하고 `A`와 `B`의 조합만 비교합니다. ALPHA의 1행과 BETA의 1, 2행이 모두 `A1, B1`으로 일치하여 다음과 같이 추출됩니다.
   * `A1, B1` (ALPHA 테이블에서 매칭)
   * `A1, B1` (BETA 테이블 1행에서 매칭)
   * `A1, B1` (BETA 테이블 2행에서 매칭)
2. **중복 제거:** 추출된 데이터셋 내에서 동일한 값을 가진 행들을 식별하고 제거하여, 고유한 결과값만 남깁니다.

---

## 3. 결과 테이블

| A | B | 비고 |
| --- | --- | --- |
| <span class="beta-data">A1</span> | <span class="beta-data">B1</span> | 중복 제거된 최종 교집합 데이터 |





---

### EXCEPT (MINUS)

두 테이블에서 **겹치는 부분을 앞의 테이블에서 제외**하여 추출하며, 추출 후에는 중복된 결과를 제거합니다. 관계형 대수의 차집합 역할을 합니다. Oracle Database에서는 지원되고, MariaDB 10.3 버전부터 `EXCEPT` 키워드로 지원됩니다. **MySQL에서는 지원되지 않아** `JOIN` 등으로 구현해야 합니다.

```sql
SELECT A, B FROM ALPHA
EXCEPT
SELECT A, B FROM BETA;
```

### 🔍쉬운설명

집합 연산자는 여러 테이블의 데이터를 합치거나 비교할 때 복잡한 연결 조건 없이 간단하게 처리할 수 있게 해주는 도구예요. 마치 다른 반 친구들의 명단을 가져와서 우리 반 명단과 합치거나, 겹치는 친구를 찾거나, 우리 반에만 있는 친구를 찾는 것과 비슷해요.

가장 중요한 규칙은 결과로 나올 **컬럼의 개수**와 **각 컬럼의 데이터 타입이 같아야** 한다는 거예요. 예를 들어, 한 테이블에서 이름(문자열), 나이(숫자)를 선택했다면, 다른 테이블에서도 이름(문자열), 나이(숫자)를 선택해야 해요. 이름과 나이의 순서도 같아야 하고요.

- **`UNION`**: 두 테이블의 내용을 모두 합쳐서 보여주되, 똑같은 데이터가 있으면 하나만 남겨요. 예를 들어, '철수, 영희, 민수'가 있는 명단 A와 '영희, 지수'가 있는 명단 B를 `UNION` 하면 '철수, 영희, 민수, 지수'가 돼요. 영희는 한 번만 나오죠. 이 과정에서 데이터를 자동으로 정렬하기 때문에 시간이 조금 걸릴 수 있어요.

- **`UNION ALL`**: `UNION`과 비슷하게 두 테이블의 내용을 모두 합쳐서 보여주지만, **중복되는 데이터도 그대로 모두 보여줘요**. 위 예시의 명단 A와 B를 `UNION ALL` 하면 '철수, 영희, 민수, 영희, 지수'가 돼요. 중복 제거 과정이나 정렬이 없어서 `UNION`보다 빠를 수 있어요.

- **`INTERSECT`**: 두 테이블에서 공통으로 존재하는 데이터만 보여줘요. 명단 A와 B에서 `INTERSECT`를 사용하면 '영희'만 남겠죠. 아쉽게도 **MySQL에서는 이 기능을 직접 제공하지 않아서**, 다른 방법(`JOIN`이나 `IN` 서브쿼리 등)을 사용해서 구현해야 해요.

- **`EXCEPT` (또는 `MINUS`)**: 첫 번째 테이블에는 있지만, 두 번째 테이블에는 없는 데이터만 보여줘요. 명단 A와 B에서 `EXCEPT`를 사용하면 '철수, 민수'가 남겠죠. `INTERSECT`와 마찬가지로 **MySQL에서는 직접 지원하지 않고**, MariaDB는 버전 10.3부터 `EXCEPT` 키워드를 지원해요. Oracle에서는 `MINUS`라는 키워드를 사용해요.

요약하자면, `UNION`은 중복 제거 후 합치고, `UNION ALL`은 중복도 그대로 합치고, `INTERSECT`는 공통 부분만, `EXCEPT/MINUS`는 차이 부분만 보여준다고 생각하면 돼요.

## 계층형 질의

테이블에 **부모-자식 관계**와 같이 계층형 데이터가 존재하는 경우 데이터를 조회하기 위해 사용하는 쿼리입니다. 주로 조직도, 게시판의 댓글, 파일 시스템 경로 등과 같이 **트리 구조의 데이터**를 다룰 때 유용합니다. 대표적인 데이터베이스로는 Oracle과 SQL Server가 계층형 질의를 지원합니다.

**계층형 데이터**: 동일 테이블에 계층적으로 **상위와 하위 데이터가 포함**되어 있는 데이터입니다. 예를 들어, 사원 테이블에서 '관리자' 컬럼이 '사원번호' 컬럼을 참조하여 사원-관리자 관계를 형성하는 경우입니다.

---

### Oracle 계층형 질의

Oracle에서는 `START WITH`와 `CONNECT BY PRIOR` 구문을 사용하여 계층형 질의를 작성합니다.

```sql
SELECT LEVEL, 자식_컬럼, 부모_컬럼, 원하는_컬럼
FROM 테이블명
START WITH 부모_컬럼 IS NULL  -- 계층의 시작(루트) 조건을 정의
CONNECT BY PRIOR 자식_컬럼 = 부모_컬럼;  -- 상위-하위 데이터 연결
```

- **`LEVEL`**: 검색 항목의 깊이를 의미하며, 루트(최상위)의 레벨이 `1`입니다.
- **`LPAD(' ', 4*(LEVEL-1)) || 컬럼명`**: `LPAD` 함수를 사용하여 `LEVEL`에 따라 들여쓰기를 표현할 수 있습니다.
- **`CONNECT_BY_ROOT`**: 현재 전개할 데이터의 **루트 데이터**를 표시합니다.
- **`CONNECT_BY_ISLEAF`**: 현재 전개할 데이터가 **리프(최하위) 데이터**인지 표시합니다. (`0` 또는 `1`)
- **`SYS_CONNECT_BY_PATH(A, B)`**: 루트 데이터부터 현재까지 전개한 **경로를 B 구분자로 연결**하여 표시합니다.

### SQL Server 계층형 질의

SQL Server 2005 버전 이후부터는 **`CTE (Common Table Expression)`** 를 이용하여 재귀 호출 방식으로 계층형 질의를 구현합니다. 이전 버전에서는 저장 프로시저의 재귀 호출이나 `While` 루프를 사용했습니다.

```sql
WITH RECURSIVE EMPLOYEES_ANCHOR AS (
    SELECT EMPLOYEEID, LASTNAME, FIRSTNAME, REPORTSTO
    FROM EMPLOYEES
    WHERE REPORTSTO IS NULL  -- 앵커 멤버 (최상위 레벨) 정의

    UNION ALL

    SELECT R.EMPLOYEEID, R.LASTNAME, R.FIRSTNAME, R.REPORTSTO
    FROM EMPLOYEES_ANCHOR A, EMPLOYEES R
    WHERE A.EMPLOYEEID = R.REPORTSTO  -- 재귀 멤버 (하위 레벨)
)
SELECT LEVEL, EMPLOYEEID, LASTNAME, FIRSTNAME, REPORTSTO
FROM EMPLOYEES_ANCHOR;
```

### MySQL / MariaDB 계층형 질의

MariaDB의 경우 **10.2 버전 이후부터** `CTE (Common Table Expression)`를 이용하여 재귀 호출 방식으로 계층형 질의를 구현합니다.

```sql
WITH RECURSIVE CTE (member_id, manager_id, lvl) AS (
    SELECT member_id, manager_id, 0 AS lvl
    FROM MEMBER
    WHERE manager_id IS NULL  -- 앵커 멤버 (최상위 레벨) 정의

    UNION ALL

    SELECT a.member_id, a.manager_id, b.lvl + 1
    FROM MEMBER a
    JOIN CTE AS b ON a.manager_id = b.member_id  -- 재귀 멤버
)
SELECT member_id, manager_id, lvl
FROM CTE
ORDER BY member_id, lvl;
```

### 🔍쉬운설명

계층형 질의는 데이터가 마치 나무 가지처럼 층층이 연결되어 있는 경우(예: 회사 조직도, 부모-자식 관계)에 사용해요. 일반적인 SQL 쿼리로는 이런 복잡한 관계를 한 번에 조회하기 어렵기 때문에 특별한 문법이 필요해요.

예를 들어, 회사의 사장님부터 말단 사원까지 누가 누구의 상사인지, 어떤 부서에 속하는지 등을 한눈에 파악하고 싶을 때 계층형 질의가 유용해요.

**계층형 데이터란?**: 한 테이블 안에 상위(부모) 데이터와 하위(자식) 데이터가 모두 들어있는 경우를 말해요. 예를 들어, 직원 테이블에 `사원번호`와 `관리자번호`가 있는데, 이 `관리자번호`가 다른 직원의 `사원번호`를 가리키는 식이죠. 이렇게 되면 누가 누구의 부하직원인지, 누가 누구의 상사인지가 한 테이블 안에서 계속 연결되는 구조가 돼요.

**Oracle에서의 계층형 질의**: Oracle 데이터베이스에서는 `CONNECT BY PRIOR`라는 특별한 구문을 사용해요.

- `START WITH`: 계층 구조의 가장 꼭대기(루트)가 어디인지 알려주는 부분이에요. 예를 들어, `START WITH 관리자 IS NULL`이라고 하면 관리자가 없는 사람(보통 사장님)을 루트로 삼겠다는 뜻이죠.

- `CONNECT BY PRIOR`: 어떤 컬럼을 기준으로 부모-자식 관계를 연결할 것인지를 알려주는 부분이에요. `CONNECT BY PRIOR 자식컬럼 = 부모컬럼`이라고 하면, 현재 행의 자식 컬럼 값이 다음 행의 부모 컬럼 값과 같을 때 연결하라는 의미예요. `PRIOR` 키워드는 "이전 단계의"라는 의미로, 현재 행을 기준으로 이전 단계의 부모 또는 자식 데이터를 지칭할 때 사용해요.

- `LEVEL`은 현재 데이터가 계층 구조에서 몇 번째 깊이에 있는지 숫자로 보여줘요. 루트는 `1`이겠죠. `LPAD` 함수를 이용해서 `LEVEL` 값에 따라 들여쓰기를 하면 조직도를 더 보기 좋게 만들 수 있어요.

**SQL Server와 MySQL/MariaDB에서의 계층형 질의**: 이 데이터베이스들은 Oracle과는 다른 **`CTE (Common Table Expression)`** 라는 방법을 사용해요. CTE는 임시 테이블을 만들어서 재귀적으로(자기 자신을 계속 호출하면서) 계층 구조를 탐색하는 방식이에요.

`WITH RECURSIVE CTE_이름 AS (...)`: 이렇게 시작하는데, 괄호 안에 `UNION ALL`을 사용해서 두 부분을 정의해요.

- **앵커 멤버 (Anchor Member)**: 계층 구조의 시작점을 정의해요. Oracle의 `START WITH`와 비슷하게, 가장 상위 레벨의 데이터를 선택하죠. 이 부분은 한 번만 실행돼요.

- **재귀 멤버 (Recursive Member)**: 앵커 멤버의 결과나 이전 재귀 멤버의 결과를 이용해서 다음 레벨의 데이터를 찾는 부분을 정의해요. 이 부분은 더 이상 새로운 데이터가 없을 때까지 반복적으로 실행돼요.

- `JOIN CTE AS b ON ...`: 재귀 멤버에서 CTE 자신을 다시 `JOIN`하여 다음 레벨의 데이터를 연결하는 방식으로 작동해요. 이 방법으로 복잡한 계층형 데이터를 효율적으로 조회할 수 있어요.

결론적으로, **계층형 질의는 복잡한 트리 형태의 데이터를 다룰 때 매우 강력한 도구**이며, 데이터베이스 종류에 따라 구현 방식에 차이가 있다는 점을 기억해야 해요.
