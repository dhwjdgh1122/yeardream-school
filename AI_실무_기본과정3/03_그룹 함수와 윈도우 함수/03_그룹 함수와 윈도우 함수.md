# SQL 윈도우 함수와 그룹 함수

---

## 데이터 분석 개요

데이터 분석을 위해 주로 사용되는 함수는 **집계 함수(Aggregate function)**, **윈도우 함수(Window function)**, **그룹 함수(Group function)** 의 세 가지 유형으로 나눌 수 있습니다.

### 🔍쉬운설명

데이터를 분석할 때 우리는 다양한 질문에 답해야 합니다. 예를 들어, "전체 직원 중 가장 급여가 높은 사람은 누구인가?", "각 부서의 평균 급여는 얼마인가?", "내 급여가 우리 부서에서 몇 등이지?"와 같은 질문들이죠. 이런 질문에 답하기 위해 SQL에서는 세 가지 종류의 "도구"를 제공합니다:

- **윈도우 함수**: 개별 행을 기준으로 다른 행들과의 관계를 정의하고 계산하는 함수입니다. 예를 들어, 특정 직원의 급여와 같은 부서 내 다른 직원들의 급여를 비교하거나, 연속된 데이터에서 이전/이후 값을 가져올 때 유용합니다. 개별 행의 특성을 유지하면서 그룹의 정보를 함께 볼 수 있습니다.

- **집계 함수**: `SUM`, `AVG`, `MAX`, `MIN`처럼 여러 행의 값을 하나로 묶어 요약하는 함수입니다. 예를 들어, 전체 직원의 평균 급여를 계산할 때 사용합니다.

- **그룹 함수**: `GROUP BY` 절과 함께 사용되어 데이터를 특정 기준(예: 부서, 직책)으로 그룹화하고 각 그룹에 대한 집계 결과를 계산하는 함수입니다. `ROLLUP`, `CUBE`, `GROUPING SETS` 등이 여기에 해당합니다. 단순히 그룹별 합계를 넘어 여러 레벨의 부분합이나 총합을 구할 때 유용합니다.

이 세 가지 함수는 데이터를 다양한 관점에서 분석하고 필요한 정보를 추출하는 데 필수적인 도구입니다.

## 윈도우 함수

**윈도우 함수**는 행과 행 사이의 순위, 집계 등 관계를 정의하는 함수입니다. 이 함수를 사용하기 위해서는 **`OVER` 구문이 필수**로 사용됩니다.

윈도우 함수의 기본 구문은 다음과 같습니다:

```sql
SELECT WINDOW_FUNCTION(ARGUMENTS)
       OVER ([PARTITION BY 칼럼] [ORDER BY 절] [WINDOWING 절])
FROM 테이블명;
```

- **`ARGUMENTS`**: 윈도우 함수에 따라 필요한 인수를 지정합니다.
- **`PARTITION BY`**: 전체 집합에 대해 소그룹으로 나누는 기준을 정의합니다. 그룹 함수에서의 `GROUP BY`와 유사하지만, `PARTITION BY`는 각 행의 개별성을 유지하면서 그룹별 계산을 가능하게 합니다.
- **`ORDER BY`**: 소그룹 내에서의 정렬 기준을 정의합니다.
- **`WINDOWING 절`**: 행에 대한 범위를 지정합니다.
  - **`ROWS`**: 물리적 단위로 행의 집합을 지정합니다.
  - **`UNBOUNDED PRECEDING`**: 윈도우의 시작 위치가 첫 번째 행입니다.
  - **`UNBOUNDED FOLLOWING`**: 윈도우의 마지막 위치가 마지막 행입니다.
  - **`CURRENT ROW`**: 윈도우의 시작 위치가 현재 행입니다.

> **MySQL 8.0.22 이상** 및 **MariaDB 10.2.0 이상** 버전에서 윈도우 함수를 지원합니다.

### 🔍쉬운설명

윈도우 함수는 데이터베이스에서 데이터를 분석할 때 아주 강력한 도구입니다. 일반적인 집계 함수(`SUM`, `AVG`)는 그룹별로 하나의 결과만 내놓는 반면, 윈도우 함수는 **개별 행의 상세 정보를 유지하면서** 특정 범위(윈도우) 내의 다른 행들과의 관계를 계산할 수 있게 해줍니다. 마치 "창문(Window)"을 통해 현재 보고 있는 행 주변의 데이터를 함께 살펴보는 것과 같습니다.

핵심은 **`OVER` 구문**입니다. 이 구문이 없으면 윈도우 함수가 아닙니다. 안에는 세 가지 주요 옵션이 있습니다:

- **`PARTITION BY`**: 이 부분은 데이터를 여러 그룹으로 "분할"합니다. 예를 들어, 부서별로 급여 순위를 매기고 싶다면 `PARTITION BY DEPARTMENT_ID`를 사용합니다. 각 부서 안에서만 별도로 계산이 이루어집니다. 중요한 것은, `GROUP BY`처럼 행을 합쳐버리지 않고, 각 행은 여전히 독립적인 결과를 가집니다.

- **`ORDER BY`**: `PARTITION BY`로 나뉜 각 그룹 내에서 데이터를 어떤 순서로 볼지 정합니다. 순위 함수에서는 이 순서가 곧 순위를 결정하는 기준이 됩니다.

- **`WINDOWING 절`** (선택 사항): 이 부분은 `ORDER BY`로 정렬된 그룹 내에서 어디부터 어디까지를 현재 행과 함께 볼지 범위를 지정합니다.
  - `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`: 현재 행까지의 모든 이전 행을 포함하여 계산합니다. (누적 합계 등에 사용)
  - `ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING`: 현재 행을 기준으로 이전 한 행과 이후 한 행을 포함하여 총 3개의 행을 봅니다.
  - `UNBOUNDED PRECEDING`은 그룹의 첫 행, `UNBOUNDED FOLLOWING`은 그룹의 마지막 행을 의미하며, `CURRENT ROW`는 말 그대로 현재 행을 의미합니다.

예를 들어, "각 직원의 급여가 자기 부서 평균 급여보다 높은지 낮은지"를 알고 싶을 때, 윈도우 함수를 사용하면 `PARTITION BY DEPARTMENT_ID`로 부서별로 나누고, 각 직원의 급여와 해당 부서의 `AVG(SALARY)`를 한 쿼리에서 동시에 볼 수 있습니다. `GROUP BY`를 사용하면 부서별 평균만 보이고 개별 직원의 급여는 사라지죠. **이것이 윈도우 함수의 큰 장점입니다.**

## 순위 함수

윈도우 함수 중 순위를 부여하는 함수는 다음과 같습니다:

| 함수 | 설명 |
|---|---|
| `RANK` | 동일한 값에는 동일한 순위를 부여하고, 다음 순위는 건너뜁니다 (예: 1, 2, 2, 4) |
| `DENSE_RANK` | `RANK`와 같이 같은 값에는 같은 순위를 부여하지만, 다음 순위를 건너뛰지 않습니다 (예: 1, 2, 2, 3) |
| `ROW_NUMBER` | 동일한 값이라도 고유한 순위를 부여합니다 (예: 1, 2, 3, 4) |

```sql
SELECT
    ID,
    NAME,
    SALARY,
    RANK() OVER (ORDER BY SALARY DESC) AS RANK,
    DENSE_RANK() OVER (ORDER BY SALARY DESC) AS DENSE_RANK,
    ROW_NUMBER() OVER (ORDER BY SALARY DESC) AS ROW_NUMBER
FROM EMPLOYEE;
```

### 🔍쉬운설명

순위 함수는 데이터에 순서를 매길 때 사용됩니다. "우리 반에서 키가 몇 등이야?", "회사에서 급여가 몇 등이지?" 같은 질문에 답하는 데 쓰이죠. **중요한 건, 같은 값에 대해 순위를 어떻게 처리할 것인가에 따라 함수가 달라진다는 점입니다.**

예를 들어, 100점, 90점, 90점, 80점이라는 성적이 있다고 해봅시다.

**`RANK()`**: 이 함수는 "공동 순위"를 인정합니다.
- 100점: 1등
- 90점: 공동 2등
- 90점: 공동 2등
- 80점: 4등

공동 2등이 두 명이라서 3등을 건너뛰고 바로 4등이 되는 것을 볼 수 있습니다.

**`DENSE_RANK()`**: 이 함수도 "공동 순위"를 인정하지만, 건너뛰지 않습니다. 순위를 "밀집"하게 부여하는 거죠.
- 100점: 1등
- 90점: 공동 2등
- 90점: 공동 2등
- 80점: 3등

`RANK()`와 달리 3등이 건너뛰어지지 않고 바로 다음 순위로 이어집니다.

**`ROW_NUMBER()`**: 이 함수는 "공동 순위"를 인정하지 않습니다. 모든 행에 고유한 순위를 부여합니다. 만약 같은 값이 있다면, `ORDER BY` 절에 추가적인 기준이 없으면 데이터베이스가 내부적으로 결정하는 순서에 따라 순위가 매겨집니다.
- 100점: 1등
- 90점 (첫 번째): 2등
- 90점 (두 번째): 3등
- 80점: 4등

이 함수는 각 행에 고유한 번호를 붙이고 싶을 때 유용합니다.

SQL 쿼리에서 이 함수들을 사용할 때는 `OVER (ORDER BY SALARY DESC)`처럼 어떤 기준으로 순위를 매길지 반드시 지정해야 합니다. `PARTITION BY`를 추가하면 부서, 그룹별로 순위를 매길 수도 있습니다. 예를 들어, `OVER (PARTITION BY DEPARTMENT_ID ORDER BY SALARY DESC)`라고 하면 각 부서 안에서만 급여가 높은 순서대로 순위가 매겨집니다.

## 일반 집계 함수

윈도우 함수에서는 `SUM`, `AVG`, `MAX`, `MIN`과 같은 **일반 집계 함수들을 `GROUP BY` 구문 없이 사용할 수 있습니다.** `OVER` 절을 사용하면 전체 데이터 또는 `PARTITION BY`로 정의된 그룹 내에서 집계 값을 계산하여 각 행에 반환할 수 있습니다.

**기존 방식 (스칼라 서브쿼리)**:
```sql
SELECT
    ID, NAME, SALARY, DEPARTMENT_ID,
    (SELECT AVG(SALARY) FROM EMPLOYEE B WHERE B.DEPARTMENT_ID = A.DEPARTMENT_ID)
FROM EMPLOYEE A
ORDER BY A.DEPARTMENT_ID;
```

**윈도우 함수 활용**:
```sql
SELECT
    ID, NAME, SALARY,
    AVG(SALARY) OVER (PARTITION BY DEPARTMENT_ID) AS DEPT_AVG_SALARY
FROM EMPLOYEE;
```

두 쿼리 모두 각 직원의 정보를 보여주면서 동시에 해당 직원이 속한 부서의 평균 급여를 함께 출력합니다. **윈도우 함수를 사용하면 스칼라 서브쿼리보다 더 간결하고 효율적인 작성이 가능합니다.**

### 🔍쉬운설명

일반적으로 `SUM`, `AVG`, `MAX`, `MIN`, `COUNT` 같은 집계 함수는 `GROUP BY`와 함께 사용되어 "그룹별"로 데이터를 요약합니다. 예를 들어, "각 부서의 평균 급여"를 구하면 부서 ID와 평균 급여만 나오고, 개별 직원의 정보는 사라집니다.

하지만 **윈도우 함수와 함께 사용하면 이야기가 달라집니다.** `AVG(SALARY) OVER (PARTITION BY DEPARTMENT_ID)`처럼 사용하면, 각 직원의 정보(ID, 이름, 급여)를 그대로 유지하면서 해당 직원이 속한 부서의 평균 급여를 함께 볼 수 있습니다.

이를 이해하기 쉽게 비유해볼게요. 회사에서 팀원들의 급여 목록을 보고 있다고 가정해봅시다.

- **집계 함수 사용**: "우리 팀의 평균 급여는 얼마야?"라고 물으면, "A팀 평균: 500만원, B팀 평균: 600만원" 이런 식으로 각 팀의 대표값만 나옵니다. 개별 팀원의 급여는 더 이상 보이지 않죠.

- **윈도우 함수로 집계 함수 사용**: "철수야, 네 급여 얼마니? 그리고 네 팀 평균 급여는 얼마니?"라고 물으면, "철수: 400만원, 철수네 팀 평균: 500만원" 이렇게 철수의 개별 정보와 함께 철수가 속한 팀의 평균 정보도 동시에 알 수 있습니다. 다른 팀원인 "영희: 600만원, 영희네 팀 평균: 500만원"처럼 개별 정보와 그룹 정보가 한 줄에 나옵니다.

즉, **윈도우 함수를 사용하면 데이터를 요약하는 동시에 원래 데이터의 상세 정보를 잃지 않는다는 큰 장점이 있습니다.** 이는 특히 개별 레코드를 기준으로 그룹 통계를 비교 분석해야 할 때 매우 유용합니다.

## 그룹 내 행 순서 함수

윈도우 함수 중 그룹 내에서 행의 순서에 따라 특정 값을 가져오는 함수는 다음과 같습니다:

| 함수 | 설명 |
|---|---|
| `FIRST_VALUE` | 윈도우 내에서 가장 먼저 나온 값을 구합니다 |
| `LAST_VALUE` | 윈도우 내에서 가장 나중에 나온 값을 구합니다 |
| `LAG` | 이전 X번째 행의 값을 가져옵니다 |
| `LEAD` | 이후 X번째 행의 값을 가져옵니다 |

**`FIRST_VALUE`, `LAST_VALUE` 예시**: 각 부서에서 급여를 가장 많이 받은 사람과 가장 적게 받은 사람의 급여를 함께 출력

```sql
SELECT
    ID, DEPARTMENT_ID, NAME, SALARY,
    FIRST_VALUE(SALARY) OVER (PARTITION BY DEPARTMENT_ID
                               ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING) AS MIN_SALARY_IN_DEPT,
    LAST_VALUE(SALARY)  OVER (PARTITION BY DEPARTMENT_ID
                               ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING) AS MAX_SALARY_IN_DEPT
FROM EMPLOYEE
ORDER BY ID;
```

> **주의**: `LAST_VALUE`는 기본 윈도우 프레임(`RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`)으로 인해 예상과 다른 결과를 줄 수 있으므로, **명시적으로 `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`과 같은 윈도우 프레임을 지정하는 것이 안전합니다.**

**`LAG`, `LEAD` 예시**: 본인 사원 번호 앞과 뒤에 해당하는 직원의 이름을 함께 출력

```sql
SELECT
    ID, NAME, SALARY,
    LAG(NAME, 1)  OVER (ORDER BY ID) AS PREV_EMPLOYEE_NAME,
    LEAD(NAME, 1) OVER (ORDER BY ID) AS AFTER_EMPLOYEE_NAME
FROM EMPLOYEE;
```

### 🔍쉬운설명

그룹 내 행 순서 함수는 특정 그룹(윈도우) 내에서 현재 보고 있는 행을 기준으로 "다른 행들의 값"을 가져올 때 사용됩니다. **시간 시리즈 데이터나 순서가 중요한 데이터에서 특히 유용합니다.**

**`FIRST_VALUE(컬럼)`**: `PARTITION BY`로 나뉜 그룹 내에서 `ORDER BY`로 정렬했을 때 가장 첫 번째 값을 가져옵니다. 예를 들어, "각 부서에서 급여가 가장 낮은 사람의 급여"를 모든 부서원 옆에 표시하고 싶을 때 사용합니다 (급여를 오름차순으로 정렬했을 때).

**`LAST_VALUE(컬럼)`**: `PARTITION BY`로 나뉜 그룹 내에서 `ORDER BY`로 정렬했을 때 가장 마지막 값을 가져옵니다. 예를 들어, "각 부서에서 급여가 가장 높은 사람의 급여"를 모든 부서원 옆에 표시하고 싶을 때 사용합니다 (급여를 오름차순으로 정렬했을 때, 주의할 점은 윈도우 프레임을 명시적으로 지정해야 합니다).

사용 시 주의사항: `LAST_VALUE`는 기본적으로 `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`라는 윈도우 프레임을 사용합니다. 이는 "현재 행까지의 모든 행"을 본다는 의미입니다. 따라서 만약 급여를 오름차순으로 정렬했다면, `LAST_VALUE`는 현재 행의 급여를 반환하게 되어 예상과 다른 결과를 줄 수 있습니다. **이 문제를 해결하려면 `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`처럼 그룹 전체를 보도록 윈도우 프레임을 명시적으로 지정해야 합니다.**

**`LAG(컬럼, N)`**: 현재 행을 기준으로 N번째 이전 행의 값을 가져옵니다. 주로 시계열 데이터에서 이전 시점의 값을 비교할 때 사용됩니다. 예를 들어, "어제 매출액 대비 오늘 매출액 변화"를 분석할 때 어제 매출액을 가져오는 데 쓸 수 있습니다.

**`LEAD(컬럼, N)`**: 현재 행을 기준으로 N번째 이후 행의 값을 가져옵니다. `LAG`와 반대로 미래 시점의 값을 가져올 때 유용합니다. 예를 들어, "다음 달 매출액 예측치"를 현재 매출액과 함께 볼 때 사용될 수 있습니다.

이 함수들은 데이터의 흐름이나 추세를 분석하거나, 특정 시점이나 위치의 값과 주변 값을 비교할 때 매우 효과적입니다.

## 그룹 내 비율 함수

윈도우 함수 중 그룹 내에서 비율을 계산하는 함수는 다음과 같습니다:

| 함수 | 설명 |
|---|---|
| `RATIO_TO_REPORT` | 파티션 내 전체 `SUM`에 대한 현재 행의 비율을 구합니다 |
| `PERCENT_RANK` | 파티션 내 순위를 백분율로 구합니다 (제일 높은 순위 행은 0, 가장 낮은 순위 행은 1) |
| `CUME_DIST` | 파티션 내 현재 행보다 작거나 같은 건들의 수 누적 백분율을 구합니다 |
| `NTILE(N)` | 파티션 내 행들을 N등분한 결과를 구합니다 |

**`RATIO_TO_REPORT` 예시**: 직원 전체 급여 합 중 각 행이 차지하는 비율을 출력

```sql
SELECT
    ID,
    NAME,
    SALARY,
    SUM(SALARY) OVER () AS TOTAL_SALARY,
    RATIO_TO_REPORT(SALARY) OVER () AS RATIO_TO_REPORT
FROM EMPLOYEE;
```

> **MariaDB의 경우** `RATIO_TO_REPORT`를 명시적으로 `(SALARY / SUM(SALARY) OVER())`와 같이 구현해야 합니다.

**`PERCENT_RANK`, `CUME_DIST` 예시**: 급여에 대한 백분율 순위 및 누적 백분율을 출력

```sql
SELECT
    ID,
    NAME,
    SALARY,
    PERCENT_RANK() OVER (ORDER BY SALARY DESC) AS PERCENT_RANK,
    ROUND(CUME_DIST() OVER (ORDER BY SALARY DESC), 4) AS CUME_DIST
FROM EMPLOYEE;
```

- **`PERCENT_RANK`**: 0 이상 1 이하의 값을 반환합니다. 가장 높은 순위는 0, 가장 낮은 순위는 1입니다.
- **`CUME_DIST`**: 0 초과 1 이하의 값을 반환합니다.

**`NTILE(N)` 예시**: 급여에 따라 직원들을 세 그룹으로 분류

```sql
SELECT
    ID,
    NAME,
    SALARY,
    NTILE(3) OVER (ORDER BY SALARY DESC) AS NTILE
FROM EMPLOYEE;
```

### 🔍쉬운설명

그룹 내 비율 함수들은 그룹 안에서 현재 행의 위치나 기여도를 **백분율이나 등급으로 나타내고자 할 때** 사용됩니다.

**`RATIO_TO_REPORT(컬럼)`**: 이 함수는 "전체 합계 중에서 현재 값이 차지하는 비율"을 계산합니다. 예를 들어, "각 직원의 급여가 회사 전체 급여 합계에서 몇 퍼센트를 차지하는가?"를 알고 싶을 때 사용합니다. `OVER()` 안에 `PARTITION BY`를 넣으면 각 그룹(예: 부서) 내의 합계에 대한 비율을 구할 수 있습니다.

**`PERCENT_RANK()`**: 이 함수는 `ORDER BY`로 정렬된 그룹 내에서 현재 행의 순위를 백분율로 나타냅니다. 결과는 0에서 1 사이의 값입니다. 가장 높은 순위(제일 잘한 사람)는 0으로, 가장 낮은 순위(제일 못한 사람)는 1로 표시됩니다. 예를 들어, "우리 반에서 내 성적이 상위 몇 퍼센트이지?"를 알고 싶을 때 사용합니다. (`RANK()`와 유사하지만 결과가 백분율로 나옴)

**`CUME_DIST()`**: 이 함수는 `PERCENT_RANK`보다 좀 더 누적 분포에 가깝습니다. `ORDER BY`로 정렬된 그룹 내에서 "현재 행보다 작거나 같은 값을 가진 행들이 전체에서 차지하는 누적 백분율"을 나타냅니다. 결과는 0 초과 1 이하의 값입니다. 예를 들어, "나보다 성적이 낮거나 같은 사람이 우리 반에서 몇 퍼센트나 되는가?"를 알 때 유용합니다.

**`NTILE(N)`**: 이 함수는 `ORDER BY`로 정렬된 그룹 내의 행들을 N개의 균등한 그룹으로 나눕니다. 그리고 각 행이 속한 그룹의 번호를 할당합니다. 예를 들어, `NTILE(3)`을 사용하면 전체 직원을 급여 순으로 3개의 등급(1등급, 2등급, 3등급)으로 나눌 수 있습니다. 이는 데이터를 고르게 분할하여 등급을 매기거나 분위수를 계산할 때 유용합니다.

이 함수들은 주로 특정 데이터 포인트의 상대적인 위치나 중요도를 파악하여 인사이트를 얻을 때 활용됩니다. 예를 들어, 고객을 VIP, 일반, 저가 고객 등으로 분류하거나, 제품의 판매량을 기준으로 등급을 매기는 등의 분석에 사용될 수 있습니다.

## 그룹 함수

데이터를 통계 내기 위해서는 전체 데이터에 대한 통계뿐만 아니라 **데이터 일부에 대한 소계, 중계 또한 필요합니다.** `UNION` 문으로 각 레벨별 SQL을 묶어 작성할 수도 있지만, ORACLE DB에서는 이러한 통계 데이터를 위한 몇 가지 함수를 제공합니다.

### 🔍쉬운설명

그룹 함수는 데이터를 특정 기준에 따라 묶어서(그룹화) 요약 통계를 내는 데 사용됩니다. 예를 들어, "각 부서의 평균 급여는 얼마인가?"와 같은 질문에 답할 때 유용하죠.

가장 기본적인 그룹화는 `GROUP BY` 절을 사용하는 것입니다. 하지만 때로는 단순히 그룹별 평균이나 합계만으로는 부족할 때가 있습니다. 예를 들어, "부서별 평균 급여"뿐만 아니라 "전체 평균 급여"도 한 번에 보고 싶거나, "부서별·직책별 평균 급여"를 보면서 "부서별 총 평균 급여"도 함께 보고 싶은 경우들이 있습니다.

이런 복잡한 통계를 내기 위해 이전에는 여러 개의 `SELECT` 문을 `UNION`으로 합쳐 사용해야 했습니다. 이는 쿼리가 길고 복잡해지며 성능에도 좋지 않았죠. 그래서 데이터베이스 시스템(특히 Oracle)에서는 이러한 다단계 통계를 더 쉽고 효율적으로 계산할 수 있도록 **`ROLLUP`, `CUBE`, `GROUPING SETS`와 같은 특별한 그룹 함수들을 제공하기 시작했습니다.** 이 함수들은 단일 쿼리로 여러 그룹 레벨의 집계를 한 번에 계산해줍니다.

---

## GROUP BY

가장 기본적인 그룹 함수로, 명시된 컬럼들을 기준으로 그룹을 형성하고 각 그룹에 대한 집계 결과를 반환합니다.

```sql
SELECT
    D.NAME AS DEPARTMENT_NAME,
    J.NAME AS JOB_NAME,
    AVG(E.SALARY) AS AVG_SALARY
FROM EMPLOYEE E
JOIN DEPARTMENT D ON E.DEPARTMENT_ID = D.ID
JOIN JOB J ON E.JOB_ID = J.ID
GROUP BY D.NAME, J.NAME
ORDER BY D.NAME, J.NAME;
```

이 쿼리는 부서와 직책별로 그룹화하여 평균 급여를 계산합니다.

### 🔍쉬운설명

`GROUP BY`는 SQL에서 데이터를 그룹으로 묶어 집계(예: 합계, 평균, 개수)를 계산할 때 가장 기본적으로 사용하는 구문입니다. 특정 컬럼의 값이 같은 행들을 하나의 그룹으로 보고, 그 그룹에 대해 집계 함수를 적용합니다.

예를 들어, "회사 전체 직원의 평균 급여"를 구하려면 `SELECT AVG(SALARY) FROM EMPLOYEE;`를 사용합니다. 하지만 "각 부서의 평균 급여"를 구하려면 `SELECT DEPARTMENT_ID, AVG(SALARY) FROM EMPLOYEE GROUP BY DEPARTMENT_ID;`처럼 `GROUP BY`를 사용해야 합니다.

강의 자료의 예시 쿼리는 `EMPLOYEE`, `DEPARTMENT`, `JOB` 세 테이블을 조인하여 **부서 이름과 직책 이름을 기준으로 그룹화하고, 각 부서·직책 조합의 평균 급여를 계산하는 것을 보여줍니다.**

결과 테이블을 보면 '개발' 부서의 '과장' 평균 급여, '개발' 부서의 '대리' 평균 급여 등, `GROUP BY` 절에 명시된 `DEPARTMENT_NAME`과 `JOB_NAME`의 모든 고유한 조합에 대해 평균 급여가 계산되어 나옵니다. 이처럼 `GROUP BY`는 데이터의 특정 특성을 기반으로 요약된 통계를 얻고자 할 때 필수적인 구문입니다.

---

## ROLLUP

**`ROLLUP` 함수는 `GROUP BY`에 지정된 컬럼들의 계층 구조를 기반으로 다양한 레벨의 소계와 총계를 계산합니다.** 그룹화하는 컬럼에 대한 부분적인 통계(소계)를 제공해줍니다.

```sql
SELECT
    D.NAME AS DEPARTMENT_NAME,
    J.NAME AS JOB_NAME,
    AVG(E.SALARY) AS AVG_SALARY
FROM EMPLOYEE E
JOIN DEPARTMENT D ON E.DEPARTMENT_ID = D.ID
JOIN JOB J ON E.JOB_ID = J.ID
GROUP BY ROLLUP(D.NAME, J.NAME);
```

이 쿼리는 `DEPARTMENT_NAME`과 `JOB_NAME`을 기준으로 그룹화하고, 다음 세 가지 레벨의 집계를 생성합니다:

1. **`DEPARTMENT_NAME`, `JOB_NAME` 별 평균 급여** (가장 상세한 레벨)
2. **`DEPARTMENT_NAME` 별 총 평균 급여** (`JOB_NAME` 컬럼이 `null`로 표시)
3. **전체 총 평균 급여** (`DEPARTMENT_NAME`과 `JOB_NAME` 컬럼 모두 `null`로 표시)

> **MariaDB의 경우** `ROLLUP`을 사용하려면 `GROUP BY D.NAME, J.NAME WITH ROLLUP;` 구문을 사용해야 합니다.

### 🔍쉬운설명

`ROLLUP`은 `GROUP BY`의 확장된 형태로, 지정된 컬럼들에 대해 **다양한 수준의 소계(subtotal)와 총계(grand total)를 한 번의 쿼리로 계산해줍니다.** 마치 데이터를 그룹화한 후, 그 그룹들을 다시 더 큰 그룹으로 묶어 요약하는 과정을 자동으로 해주는 것과 같습니다.

`ROLLUP(컬럼1, 컬럼2, 컬럼3)`과 같이 사용하면 다음과 같은 그룹화 조합에 대한 집계를 계산합니다:

- `(컬럼1, 컬럼2, 컬럼3)`: 가장 상세한 그룹 (예: 부서·직책별)
- `(컬럼1, 컬럼2)`: 컬럼3에 대한 총계 (예: 부서별 총 직책)
- `(컬럼1)`: 컬럼2에 대한 총계 (예: 부서별 총계)
- `()`: 모든 컬럼에 대한 총계 (전체 총계)

강의 자료의 예시 `ROLLUP(D.NAME, J.NAME)`은 다음과 같은 세 가지 레벨의 통계를 제공합니다:

- **부서 이름과 직책 이름별 평균 급여**: `GROUP BY D.NAME, J.NAME`과 동일한 결과입니다. (예: 개발·과장 평균 급여)
- **부서 이름별 총 평균 급여**: `J.NAME` 컬럼이 `(null)`로 표시된 행들이 이에 해당합니다. 이는 특정 부서의 모든 직책에 대한 평균 급여를 의미합니다. (예: 개발 부서 전체 평균 급여)
- **전체 총 평균 급여**: `D.NAME`과 `J.NAME` 컬럼이 모두 `(null)`로 표시된 행이 이에 해당합니다. 이는 회사 전체 직원의 평균 급여를 의미합니다.

`ROLLUP`은 주로 **계층적인 데이터를 다룰 때 유용하며**, 보고서나 요약 데이터를 만들 때 여러 쿼리를 작성할 필요 없이 한 번에 다양한 수준의 요약을 얻을 수 있도록 도와줍니다. `(null)` 값은 실제 데이터가 없는 것이 아니라, 해당 컬럼의 그룹화가 "총계"를 의미한다는 표시입니다.

---

## CUBE

**`CUBE` 함수는 `ROLLUP` 함수에서 제공하는 결과를 포함하여, 그룹화하는 컬럼에 대해 가능한 모든 경우의 수에 대한 다차원 집계를 생성합니다.**

```sql
SELECT
    D.NAME AS DEPARTMENT_NAME,
    J.NAME AS JOB_NAME,
    AVG(E.SALARY) AS AVG_SALARY
FROM EMPLOYEE E
JOIN DEPARTMENT D ON E.DEPARTMENT_ID = D.ID
JOIN JOB J ON E.JOB_ID = J.ID
GROUP BY CUBE(D.NAME, J.NAME);
```

`CUBE(D.NAME, J.NAME)`은 다음 **네 가지** 레벨의 집계를 생성합니다:

1. **`DEPARTMENT_NAME`, `JOB_NAME` 별 평균 급여** (가장 상세한 레벨)
2. **`DEPARTMENT_NAME` 별 총 평균 급여** (`JOB_NAME` 컬럼이 `null`로 표시)
3. **`JOB_NAME` 별 총 평균 급여** (`DEPARTMENT_NAME` 컬럼이 `null`로 표시)
4. **전체 총 평균 급여** (`DEPARTMENT_NAME`과 `JOB_NAME` 컬럼 모두 `null`로 표시)

> **MariaDB의 경우** `CUBE`를 사용하려면 `GROUP BY D.NAME, J.NAME WITH ROLLUP`을 두 번 `UNION`으로 결합하는 방식으로 구현해야 합니다.

### 🔍쉬운설명

`CUBE` 함수는 `ROLLUP`보다 더욱 강력한 그룹화 도구입니다. `ROLLUP`이 계층적인 총계(예: 지역 > 도시 > 동)를 제공하는 반면, **`CUBE`는 지정된 모든 컬럼의 가능한 모든 조합에 대한 총계를 계산합니다.** 마치 다차원 큐브를 돌려보면서 모든 각도에서 데이터를 요약해 보는 것과 같습니다.

`CUBE(컬럼1, 컬럼2)`와 같이 사용하면 2의 N승(여기서는 2² = 4) 가지 그룹화 조합에 대한 집계를 계산합니다:

- `(컬럼1, 컬럼2)`: 가장 상세한 그룹 (예: 부서·직책별)
- `(컬럼1)`: 컬럼2에 대한 총계 (예: 부서별 총계)
- `(컬럼2)`: 컬럼1에 대한 총계 (예: 직책별 총계)
- `()`: 모든 컬럼에 대한 총계 (전체 총계)

강의 자료의 예시 `CUBE(D.NAME, J.NAME)`은 다음과 같은 네 가지 레벨의 통계를 제공합니다:

- **부서 이름과 직책 이름별 평균 급여**: (예: 개발·과장 평균 급여)
- **부서 이름별 총 평균 급여**: `J.NAME`이 `(null)`인 경우. (예: 개발 부서 전체 평균 급여)
- **직책 이름별 총 평균 급여**: `D.NAME`이 `(null)`인 경우. (예: 모든 부서의 과장 평균 급여)
- **전체 총 평균 급여**: `D.NAME`과 `J.NAME`이 모두 `(null)`인 경우. (예: 회사 전체 평균 급여)

`CUBE`는 **비즈니스 인텔리전스(BI)나 데이터 웨어하우징에서 여러 차원의 데이터를 분석할 때 매우 유용합니다.** 모든 가능한 관점에서 요약 데이터를 얻을 수 있어, 숨겨진 패턴이나 트렌드를 발견하는 데 도움을 줄 수 있습니다. MariaDB처럼 직접 지원하지 않는 경우 `ROLLUP`과 `UNION`을 조합하여 구현할 수 있지만, 이는 쿼리를 더 복잡하게 만듭니다.

## GROUPING SETS

**`GROUPING SETS`는 명시된 컬럼에 대해 개별 통계를 생성합니다.** 각 컬럼에 대해 `GROUP BY`로 생성한 통계를 모두 `UNION ALL` 한 결과와 동일합니다.

```sql
SELECT
    D.NAME AS DEPARTMENT_NAME,
    J.NAME AS JOB_NAME,
    AVG(E.SALARY) AS AVG_SALARY
FROM EMPLOYEE E
JOIN DEPARTMENT D ON E.DEPARTMENT_ID = D.ID
JOIN JOB J ON E.JOB_ID = J.ID
GROUP BY GROUPING SETS(D.NAME, J.NAME);
```

이 쿼리는 `DEPARTMENT_NAME` 기준의 평균 급여와 `JOB_NAME` 기준의 평균 급여를 각각 계산하여 합칩니다. 이는 다음 두 개의 `GROUP BY` 쿼리를 `UNION ALL`로 합친 것과 같습니다:

```sql
-- GROUP BY D.NAME
-- UNION ALL
-- GROUP BY J.NAME
```

> **MariaDB에서** `GROUPING SETS(D.NAME, J.NAME)`은 `UNION ALL`을 사용한 방식으로 구현할 수 있습니다.

### 🔍쉬운설명

`GROUPING SETS`는 `ROLLUP`이나 `CUBE`와 달리, **개발자가 원하는 특정 그룹화 조합만 선택하여 집계할 수 있도록 해줍니다.** `ROLLUP`과 `CUBE`가 "모든 계층적 조합" 또는 "모든 가능한 조합"을 자동으로 생성하는 데 반해, `GROUPING SETS`는 "내가 원하는 이 조합들만 해줘"라고 명시적으로 지시하는 것과 같습니다.

`GROUPING SETS((컬럼1, 컬럼2), (컬럼3), ())`처럼 사용할 수 있습니다. 여기서 각 괄호 `()` 안의 내용이 하나의 그룹화 기준이 됩니다.

강의 자료의 예시 `GROUPING SETS(D.NAME, J.NAME)`은 다음 두 가지 그룹화 조합에 대한 평균 급여를 계산하여 하나의 결과 집합으로 보여줍니다:

- **`GROUP BY D.NAME`과 동일**: 각 부서별 평균 급여를 계산합니다. 이때 `J.NAME` 컬럼은 `(null)`로 표시됩니다.
- **`GROUP BY J.NAME`과 동일**: 각 직책별 평균 급여를 계산합니다. 이때 `D.NAME` 컬럼은 `(null)`로 표시됩니다.

결과를 보면 '영업' 부서의 총 평균 급여(`J.NAME`이 null)와 '개발' 부서의 총 평균 급여가 보이고, 동시에 '과장'의 총 평균 급여(`D.NAME`이 null), '팀장'의 총 평균 급여 등 직책별 평균도 함께 표시됩니다.

`GROUPING SETS`는 여러 `GROUP BY` 절을 `UNION ALL`로 합친 것과 기능적으로 동일하지만, **더 간결하고 효율적인 쿼리 작성을 가능하게 합니다.** 특히 필요 없는 총계나 소계는 제외하고, 딱 필요한 그룹화 조합에 대한 통계만 보고 싶을 때 유용하게 사용됩니다.
