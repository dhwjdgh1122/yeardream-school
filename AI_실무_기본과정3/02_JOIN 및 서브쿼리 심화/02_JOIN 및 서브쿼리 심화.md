# JOIN

## 요약

이 강의 자료는 SQL을 사용하여 데이터를 다루는 심화 과정 중 **JOIN**에 대해 상세히 설명합니다. JOIN의 기본적인 개념부터 FROM 절 JOIN 형태(INNER, USING, NATURAL, CROSS, OUTER JOIN) 및 셀프 조인까지 다양한 JOIN 방식을 예시와 함께 다루어 효율적인 데이터 조회를 돕습니다.

---

## 1. JOIN의 개념

**JOIN**은 두 개 이상의 테이블을 연결하거나 결합하여 데이터를 출력하는 작업을 의미합니다.

JOIN 방식은 사용되는 연산자에 따라 크게 **EQUI JOIN**과 **Non EQUI JOIN**으로 분류됩니다.

### 🔍쉬운설명

JOIN은 여러 개의 엑셀 시트(테이블)에 흩어져 있는 정보를 한눈에 볼 수 있도록 합치는 작업이라고 생각하면 쉽습니다. 예를 들어, 한 시트에는 학생 정보가 있고 다른 시트에는 수강 과목 정보가 있을 때, JOIN을 사용하면 어떤 학생이 어떤 과목을 듣고 있는지 한 번에 확인할 수 있습니다.

JOIN은 크게 두 가지로 나뉘는데, 하나는 **EQUI JOIN**이고 다른 하나는 **Non EQUI JOIN**입니다.

---

### 1.1. EQUI JOIN (등가 교집합)

**EQUI JOIN**은 두 테이블 간에 **정확하게 일치하는 경우**를 활용하는 조인입니다. 주로 **등가 연산자(`=`)** 를 사용하여 조건을 지정하며, 대부분 **기본키-외래키 관계**를 기반으로 발생하지만 모든 조인이 이 관계에 국한되는 것은 아닙니다.

### 🔍쉬운설명

EQUI JOIN은 "정확히 같은 것끼리만 연결해 줘!"라고 요청하는 조인입니다. 예를 들어, USER 테이블에 `CLASS_ID`가 `'001'`인 사용자가 있고, CLASS 테이블에도 `ID`가 `'001'`인 클래스가 있다면, 이 두 `'001'`을 기준으로 테이블을 연결하는 것이 EQUI JOIN입니다. 이때 사용하는 연산자는 항상 '같다'는 의미의 `=`입니다. 주로 USER 테이블의 `CLASS_ID`가 CLASS 테이블의 `ID`를 참조하는 것처럼, 서로 다른 테이블이지만 **특정 컬럼의 값이 정확히 일치할 때** 사용합니다.

---

### 1.2. Non EQUI JOIN (비등가 교집합)

**Non EQUI JOIN**은 두 테이블 간에 **정확하게 일치하지 않는 경우**를 활용하는 조인입니다. 등가 연산자(`=`) 이외의 다양한 연산자들(`>`, `>=`, `<=`, `<`, `BETWEEN`)을 사용하여 조인 조건을 정의합니다.

### 🔍쉬운설명

Non EQUI JOIN은 EQUI JOIN과는 반대로, "정확히 같지 않아도 돼, 범위 안에 있거나 크거나 작은 경우에도 연결해 줘!"라고 요청하는 조인입니다. 예를 들어, 직원의 급여 등급을 나누는 GRADE 테이블과 직원의 급여가 있는 EMPLOYEE 테이블이 있다고 가정해봅시다. EMPLOYEE 테이블의 급여가 GRADE 테이블의 최소\_급여와 최대\_급여 사이에 있을 때 두 테이블을 연결하고 싶다면 `BETWEEN` 연산자를 사용한 Non EQUI JOIN을 사용합니다. 이처럼 `=`가 아닌 다른 비교 연산자를 사용하면 **Non EQUI JOIN**입니다.

---

## 2. FROM 절 JOIN 형태

### 2.1. INNER JOIN (내부 조인)

**INNER JOIN**은 JOIN 조건에서 **동일한 값이 있는 행만 반환**합니다. 이는 JOIN의 **기본값**이며, SQL 쿼리에서 `INNER` 키워드는 생략할 수 있습니다. `ON` 구문을 사용하여 조인 조건을 명시적으로 지정합니다.

```sql
SELECT *
FROM 테이블1 [INNER] JOIN 테이블2
ON 테이블1.컬럼명 = 테이블2.컬럼명;
```

### 🔍쉬운설명

INNER JOIN은 두 개 이상의 테이블에서 **겹치는 부분만 보여주는** 조인입니다. 마치 벤 다이어그램에서 두 원이 겹치는 가운데 부분만 보여주는 것과 같습니다. 예를 들어, USER 테이블과 CLASS 테이블이 있을 때, INNER JOIN을 사용하면 두 테이블 모두에 존재하는 `CLASS_ID`를 가진 사용자 정보와 클래스 정보만 나타납니다. 만약 어떤 사용자가 `CLASS_ID`가 없거나, 어떤 클래스에 해당 `CLASS_ID`를 가진 사용자가 없다면, 그 정보는 결과에서 제외됩니다.

INNER JOIN은 SQL에서 가장 흔하게 사용되는 조인 방식이며, `JOIN`이라고만 써도 기본적으로 INNER JOIN으로 인식합니다. `ON` 키워드 뒤에 어떤 기준으로 테이블을 합칠지 조건을 명확히 써주면 됩니다.

---

### 2.2. USING 조건절

**USING 조건절**은 두 테이블 간 **같은 이름을 가진 칼럼들 중에서 원하는 칼럼에 대해서만 선택적으로 등가 조인**을 수행할 때 사용됩니다. USING 조건절 사용 시에는 **칼럼이나 테이블에 별칭을 붙일 수 없습니다**. SQL Server에서는 지원하지 않습니다.

```sql
SELECT *
FROM 테이블1 JOIN 테이블2
USING(기준칼럼);
```

### 🔍쉬운설명

USING 조건절은 INNER JOIN과 비슷하지만, **조인하려는 두 테이블에 이름이 같은 컬럼이 있을 때** 유용하게 사용할 수 있습니다. 예를 들어, USER 테이블에 `CLASS_ID`가 있고 CLASS 테이블에도 `CLASS_ID`라는 컬럼이 있을 경우, `ON USER.CLASS_ID = CLASS.CLASS_ID` 대신 `USING(CLASS_ID)`라고 간결하게 표현할 수 있습니다. 이때 주의할 점은 USING을 쓸 때는 테이블이나 컬럼에 `a.CLASS_ID`처럼 **별칭(`a.`)을 붙일 수 없다**는 것입니다. 이 기능은 SQL Server에서는 작동하지 않으니 주의해야 합니다.

---

### 2.3. NATURAL JOIN (자연 조인)

**NATURAL JOIN**은 두 테이블 간의 **동일한 이름을 갖는 모든 칼럼들에 대해 등가 조인**을 수행합니다. NATURAL JOIN 사용 시 추가로 `ON` 조건절이나 `USING` 조건절, `WHERE` 절에서 JOIN 조건을 정의할 수 없습니다. 또한, INNER JOIN과 달리 **테이블에 별칭을 지정할 수 없습니다**.

```sql
SELECT *
FROM 테이블1 NATURAL JOIN 테이블2;
```

### 🔍쉬운설명

NATURAL JOIN은 개발자가 따로 조건을 지정하지 않아도, SQL이 알아서 **이름이 같고 데이터 타입이 같은 모든 컬럼**을 찾아서 자동으로 조인을 수행해줍니다. 예를 들어, USER 테이블과 CLASS 테이블에 모두 `CLASS_ID`라는 컬럼이 있다면, NATURAL JOIN은 자동으로 이 `CLASS_ID`를 기준으로 두 테이블을 합쳐줍니다. 편리해 보이지만, **예상치 못한 컬럼이 같아서 원치 않는 조인이 발생할 수도 있어** 주의가 필요합니다. 또한, NATURAL JOIN을 사용하면 추가적인 조인 조건을 사용하거나, 테이블에 별칭을 붙일 수 없습니다.

---

### 2.4. CROSS JOIN (교차 조인)

**CROSS JOIN**은 JOIN 조건이 없는 경우에 생길 수 있는 **모든 데이터의 조합**을 조회합니다. 즉, 한 테이블의 모든 행과 다른 테이블의 모든 행을 결합하여 가능한 모든 경우의 수를 생성합니다. 이를 **카르테시안 곱(Cartesian Product)** 이라고도 합니다.

```sql
-- 방법 1
SELECT *
FROM 테이블1 CROSS JOIN 테이블2;

-- 방법 2 (WHERE 조건이 없으면 CROSS JOIN)
SELECT *
FROM 테이블1, 테이블2;
```

### 🔍쉬운설명

CROSS JOIN은 두 테이블의 **모든 행을 서로 짝지어 연결**하는 조인입니다. 마치 수학에서 모든 경우의 수를 따지는 '카르테시안 곱'과 같습니다. 예를 들어, PERSON 테이블에 2명의 사람이 있고, PUBLIC_TRANSPORT 테이블에 3가지 종류의 교통수단이 있다면, CROSS JOIN을 수행하면 2 × 3 = 6개의 모든 조합이 결과로 나옵니다. 조인 조건이 따로 없기 때문에, **무분별하게 사용하면 엄청나게 많은 데이터가 생성될 수 있어** 주의해야 합니다. 보통 특정 분석이나 샘플 데이터 생성 시에 사용될 수 있습니다.

---

### 2.5. OUTER JOIN (외부 조인)

**OUTER JOIN**은 두 개의 테이블 간에 교집합을 조회할 뿐만 아니라, **한쪽 테이블에만 있는 데이터도 포함시켜 조회**합니다. 이때, 빈 곳은 **`NULL` 값으로 출력**됩니다. WHERE 조건절에서 한쪽에만 있는 데이터를 포함시킬 테이블의 반대쪽에 `(+)`를 위치시키는 방식으로 Oracle DB에서 사용됩니다.

### 🔍쉬운설명

OUTER JOIN은 INNER JOIN과는 달리, **겹치는 부분뿐만 아니라 어느 한쪽에만 있는 데이터까지 모두 보고 싶을 때** 사용합니다. 벤 다이어그램으로 치면, 두 원이 겹치는 부분과 함께 어느 한쪽 원의 전체 또는 나머지 부분까지 보여주는 것입니다. 이때 다른 쪽에 데이터가 없는 부분은 **`NULL` 값으로 표시**됩니다.

---

#### 2.5.1. 표준 OUTER JOIN (LEFT JOIN)

**LEFT JOIN**은 **왼쪽 테이블의 모든 데이터를 포함**하고, 오른쪽 테이블에서는 조인 조건에 일치하는 데이터만 가져옵니다. 일치하는 데이터가 없는 경우 오른쪽 테이블의 칼럼들은 **`NULL`로 채워집니다**.

```sql
SELECT *
FROM USER LEFT [OUTER] JOIN CLASS
ON USER.CLASS_ID = CLASS.CLASS_ID;
```

### 🔍쉬운설명

LEFT JOIN은 "왼쪽에 있는 테이블의 모든 데이터를 보여줘, 그리고 오른쪽에 일치하는 데이터가 있으면 같이 보여주고, 없으면 그냥 비워 둬(`NULL`로 표시해 줘)"라고 요청하는 것입니다. 예를 들어, USER 테이블과 CLASS 테이블이 있을 때, LEFT JOIN을 사용하면 **모든 사용자 정보는 일단 다 나옵니다**. 그 사용자가 듣고 있는 클래스가 CLASS 테이블에 있으면 클래스 정보가 같이 나오고, 듣는 클래스가 없으면 클래스 관련 정보는 `NULL`로 표시됩니다.

---

#### 2.5.2. 표준 OUTER JOIN (RIGHT JOIN)

**RIGHT JOIN**은 **오른쪽 테이블의 모든 데이터를 포함**하고, 왼쪽 테이블에서는 조인 조건에 일치하는 데이터만 가져옵니다. 일치하는 데이터가 없는 경우 왼쪽 테이블의 칼럼들은 **`NULL`로 채워집니다**.

```sql
SELECT *
FROM USER RIGHT [OUTER] JOIN CLASS
ON USER.CLASS_ID = CLASS.CLASS_ID;
```

### 🔍쉬운설명

RIGHT JOIN은 LEFT JOIN과 반대로, "오른쪽에 있는 테이블의 모든 데이터를 보여줘, 그리고 왼쪽에 일치하는 데이터가 있으면 같이 보여주고, 없으면 비워 둬(`NULL`로 표시해 줘)"라고 요청하는 것입니다. USER 테이블과 CLASS 테이블 예시에서 RIGHT JOIN을 사용하면, **모든 클래스 정보는 일단 다 나옵니다**. 그 클래스를 수강하는 사용자가 USER 테이블에 있으면 사용자 정보가 같이 나오고, 수강하는 사용자가 없으면 사용자 관련 정보는 `NULL`로 표시됩니다.

---

#### 2.5.3. 표준 OUTER JOIN (FULL OUTER JOIN)

**FULL OUTER JOIN**은 왼쪽 테이블과 오른쪽 테이블 **모든 데이터를 포함**하며, 조인 조건에 일치하는 데이터가 없는 경우 해당 칼럼들을 **`NULL`로 채웁니다**. MySQL에서는 FULL OUTER JOIN을 직접 지원하지 않으므로, `LEFT OUTER JOIN`과 `RIGHT OUTER JOIN`을 `UNION` 연산자로 결합하여 구현합니다.

```sql
SELECT *
FROM CLASS FULL OUTER JOIN USER
ON USER.CLASS_ID = CLASS.CLASS_ID;
```

MySQL에서의 FULL OUTER JOIN 구현:

```sql
SELECT *
FROM CLASS LEFT OUTER JOIN USER
ON USER.CLASS_ID = CLASS.CLASS_ID

UNION

SELECT *
FROM CLASS RIGHT OUTER JOIN USER
ON USER.CLASS_ID = CLASS.CLASS_ID;
```

**`UNION` 연산자는 중복 데이터를 제거합니다** (중앙 교집합 부분에 대한 중복을 제거해줌).

### 🔍쉬운설명

FULL OUTER JOIN은 "왼쪽 테이블의 모든 데이터, 오른쪽 테이블의 모든 데이터, 그리고 둘 다 겹치는 데이터까지 전부 보여줘!"라고 요청하는 조인입니다. 즉, 어떤 테이블에만 있는 데이터든, 두 테이블 모두에 있는 데이터든 **가리지 않고 다 보여줍니다**. 벤 다이어그램으로 치면, 두 원이 이루는 전체 영역을 다 보여주는 것과 같습니다. 데이터가 없는 부분은 마찬가지로 `NULL`로 표시됩니다.

MySQL에서는 `FULL OUTER JOIN` 키워드를 직접 사용할 수 없습니다. 대신, `LEFT OUTER JOIN`을 통해 왼쪽 테이블의 모든 데이터와 겹치는 부분을 가져오고, `RIGHT OUTER JOIN`을 통해 오른쪽 테이블의 모든 데이터와 겹치는 부분을 가져온 다음, 이 두 결과를 **`UNION` 연산자로 합쳐서** FULL OUTER JOIN과 같은 효과를 냅니다.

`UNION`은 중복되는 행을 자동으로 제거해주기 때문에, 겹치는 부분이 한 번만 나타나게 됩니다.

---

### 2.6. INNER vs OUTER vs CROSS JOIN 비교

각 JOIN 유형에 따라 출력되는 행의 개수와 데이터 조합이 달라집니다.

| JOIN 유형 | 설명 |
|---|---|
| **INNER JOIN** | 양쪽 테이블에 모두 일치하는 행만 출력 |
| **LEFT JOIN** | 왼쪽 테이블의 모든 행과 오른쪽 테이블에서 일치하는 행 출력 (불일치 시 `NULL`) |
| **RIGHT JOIN** | 오른쪽 테이블의 모든 행과 왼쪽 테이블에서 일치하는 행 출력 (불일치 시 `NULL`) |
| **FULL OUTER JOIN** | 양쪽 테이블의 모든 행 출력 (불일치 시 `NULL`) |
| **CROSS JOIN** | 양쪽 테이블의 모든 행을 가능한 모든 조합으로 출력 (카르테시안 곱) |

---

### 2.7. JOIN과 WHERE 절

JOIN을 활용한 쿼리에서도 기존과 같이 **`WHERE` 문을 이용하여 조건을 걸 수 있습니다**. JOIN 조건을 `ON` 절에 명시하고, 추가적인 필터링 조건을 `WHERE` 절에 사용하여 원하는 데이터를 더욱 정확하게 조회할 수 있습니다.

```sql
SELECT *
FROM USER a JOIN CLASS b
ON a.CLASS_ID = b.ID
WHERE a.NAME = '모자장수';
```

### 🔍쉬운설명

JOIN으로 테이블을 합친 후에, 합쳐진 데이터들 중에서 **특정 조건에 맞는 행만 걸러내고 싶을 때** `WHERE` 절을 사용합니다. 예를 들어, USER 테이블과 CLASS 테이블을 `CLASS_ID`로 JOIN한 후에, 그 결과 중에서 USER의 이름이 '모자장수'인 행만 보고 싶을 때 `WHERE NAME = '모자장수'` 조건을 추가할 수 있습니다. **`ON` 절은 테이블을 어떻게 합칠지 JOIN 조건을 정의**하고, **`WHERE` 절은 최종적으로 어떤 데이터를 보여줄지 필터링**하는 역할을 합니다.

---

## 3. 셀프 조인

### 3.1. 셀프 조인이란?

**셀프 조인**은 **동일 테이블 사이의 조인**을 의미합니다. 동일 테이블 간의 조인을 수행할 때는 테이블과 칼럼 이름이 모두 동일하기 때문에, 각 테이블을 식별하기 위해 **별칭(ALIAS)을 지정하는 것이 필수**입니다.

### 🔍쉬운설명

셀프 조인은 말 그대로 **자기 자신과 조인하는 것**입니다. 보통 JOIN은 서로 다른 두 테이블을 연결할 때 사용하지만, 때로는 하나의 테이블 안에서 특정 정보를 기준으로 스스로를 연결해야 할 때가 있습니다. 예를 들어, 직원 테이블에서 각 직원의 관리자가 누구인지 알아내야 할 때, 관리자 정보도 같은 직원 테이블에 있는 경우가 많습니다. 이때는 마치 두 개의 똑같은 직원 테이블이 있다고 가정하고, 하나는 직원 정보로, 다른 하나는 관리자 정보로 활용하여 조인을 수행합니다. 이때 가장 중요한 것은 두 테이블이 실제로는 같은 테이블이기 때문에, 이들을 구분하기 위해 **`ALPHA`, `BETA`와 같은 별칭을 꼭 붙여줘야 한다**는 점입니다.

---

### 3.2. 셀프 조인 예시

셀프 조인은 주로 **계층형 질의**에서 활용됩니다. 예를 들어, 직원 테이블에서 각 직원의 관리자 정보를 조회할 때 사용될 수 있습니다.

```sql
SELECT ALPHA.칼럼명, BETA.칼럼명, ...
FROM 테이블1 ALPHA, 테이블1 BETA
WHERE ALPHA.컬럼명2 = BETA.컬럼명1;
```

---

#### 3.2.1. 계층형 질의 예시

직원 테이블에서 `사원번호`와 `관리자` 컬럼이 있을 때, 각 직원의 **관리자의 관리자(차상위 관리자)** 가 누구인지 등을 조회할 수 있습니다. `ALPHA` 테이블은 직원 정보를 나타내고, `BETA` 테이블은 관리자 정보를 나타내는 가상의 테이블 역할을 합니다.

```sql
SELECT ALPHA.사원번호, ALPHA.관리자, BETA.관리자 AS 차상위_관리자
FROM 직원 ALPHA, 직원 BETA
WHERE ALPHA.관리자 = BETA.사원번호;
```

### 🔍쉬운설명

셀프 조인은 특히 **'누구의 상사는 누구인가?'와 같은 계층 관계를 하나의 테이블 안에서 찾아낼 때** 유용합니다. 예를 들어 직원 테이블에 `사원번호`와 `관리자(사원번호)` 컬럼이 있다고 해봅시다. '엘리스' 직원의 `관리자`가 '모자장수'라면, '엘리스'의 `관리자` 컬럼에는 '모자장수'의 `사원번호`가 적혀 있을 것입니다.

이때 셀프 조인을 사용하면, '직원' 테이블을 `ALPHA`라는 이름의 '직원 테이블'과 `BETA`라는 이름의 '관리자 테이블'로 두 개처럼 활용합니다.

- `ALPHA`는 현재 직원의 정보를 나타내고, `ALPHA.관리자`는 이 직원의 관리자 `사원번호`를 의미합니다.
- `BETA`는 관리자 정보를 나타내고, `BETA.사원번호`는 관리자 본인의 `사원번호`를 의미합니다.

이제 **`ALPHA.관리자 = BETA.사원번호`** 라는 조건을 통해, '현재 직원의 관리자 사원번호'와 '관리자 본인의 사원번호'를 일치시켜 조인을 합니다. 이렇게 하면 각 직원의 관리자가 누구인지, 그리고 그 관리자의 다른 정보(예: 관리자의 관리자)까지 한 테이블에서 쉽게 찾아낼 수 있습니다.

# 서브쿼리 심화

## 요약

이 강의 자료는 SQL 서브쿼리에 대한 심층적인 이해를 목표로 하며, 서브쿼리의 동작 방식과 반환되는 데이터 형태에 따른 분류, 스칼라 서브쿼리의 활용, 그리고 **뷰(View)** 의 개념과 장단점 및 사용법을 다룹니다.

---

## 1. 동작하는 방식에 따른 서브쿼리 분류

서브쿼리는 **메인 쿼리의 컬럼이 서브쿼리에 포함되는지 여부**에 따라 **연관 서브쿼리(Correlated Subquery)** 와 **비연관 서브쿼리(Un-Correlated Subquery)** 로 나눌 수 있습니다.

---

### 연관 서브쿼리 (Correlated Subquery)

**연관 서브쿼리**는 **메인 쿼리의 컬럼이 서브쿼리에 포함**되며, 메인 쿼리의 컬럼이 서브쿼리 내에서 특정 조건으로 사용됩니다. 이는 **메인 쿼리의 각 행에 대해 서브쿼리가 반복적으로 실행**되어 결과를 도출합니다.

예시: 본인이 속한 부서의 평균 급여보다 높은 급여를 받는 직원들을 출력하는 경우

```sql
SELECT ID, DEPARTMENT_ID, NAME, SALARY
FROM EMPLOYEE A
WHERE SALARY > (
    SELECT AVG(SALARY)
    FROM EMPLOYEE B
    WHERE B.DEPARTMENT_ID = A.DEPARTMENT_ID
);
```

### 🔍쉬운설명

연관 서브쿼리는 메인 쿼리와 서브쿼리가 **서로 긴밀하게 연결되어 동작**하는 서브쿼리입니다. 마치 "너희 반에서 평균 점수보다 높은 학생들을 찾아라"라고 할 때, 각 반(메인 쿼리의 한 행)마다 평균 점수(서브쿼리)를 계산하고 그 평균을 기준으로 학생들을 찾는 것과 같습니다. **메인 쿼리의 한 행이 처리될 때마다 서브쿼리가 해당 행의 정보를 이용해 실행**되기 때문에, 서브쿼리가 여러 번 실행될 수 있습니다. 위 예시에서는 `EMPLOYEE A` 테이블의 각 직원에 대해, 해당 직원의 부서(`A.DEPARTMENT_ID`)와 동일한 부서(`B.DEPARTMENT_ID`)의 평균 급여를 서브쿼리가 계산하고, 이 평균보다 급여가 높은 직원을 찾습니다.

---

### 비연관 서브쿼리 (Un-Correlated Subquery)

**비연관 서브쿼리**는 **메인 쿼리의 컬럼이 서브쿼리에 포함되지 않으며**, 주로 메인 쿼리에 특정한 값을 제공할 때 사용됩니다. **서브쿼리가 메인 쿼리와 독립적으로 한 번만 실행**되어 그 결과를 메인 쿼리에 전달합니다.

예시: ELICE가 속한 부서의 평균 급여를 출력하는 경우

```sql
SELECT AVG(SALARY)
FROM EMPLOYEE
WHERE DEPARTMENT_ID = (
    SELECT DEPARTMENT_ID
    FROM EMPLOYEE
    WHERE NAME = 'ELICE'
);
```

### 🔍쉬운설명

비연관 서브쿼리는 메인 쿼리와는 **독립적으로 먼저 실행되어 하나의 결과값을 만들고**, 그 결과값을 메인 쿼리가 사용합니다. 마치 "서울의 평균 기온을 알려줘"라고 하면 서울의 평균 기온(서브쿼리 결과)을 먼저 알아낸 다음, 그 값을 다른 계산에 활용하는 것과 같습니다. **서브쿼리가 한 번만 실행**되므로, 연관 서브쿼리보다 성능 면에서 유리한 경우가 많습니다. 위 예시에서는 먼저 `'ELICE'`라는 이름의 직원이 속한 부서의 `ID`를 서브쿼리에서 찾아내고, 이 부서 `ID`를 사용하여 해당 부서 직원들의 평균 급여를 메인 쿼리에서 계산합니다.

---

## 2. 반환되는 데이터 형태에 따른 서브쿼리 분류

서브쿼리는 반환되는 데이터의 형태에 따라 **단일 행 서브쿼리(Single Row Subquery)**, **다중 행 서브쿼리(Multi Row Subquery)**, **다중 컬럼 서브쿼리(Multi Column Subquery)** 로 분류됩니다.

---

### 단일 행 서브쿼리 (Single Row Subquery)

**단일 행 서브쿼리**는 서브쿼리의 결과가 **한 개의 행을 반환**하며, 단일 행 비교 연산자(`=`, `<`, `>`, `<=`, `>=`)와 같이 사용됩니다.

예시: ELICE가 속한 부서의 직원들을 출력하는 경우

```sql
SELECT ID, NAME, SALARY
FROM EMPLOYEE
WHERE DEPARTMENT_ID = (
    SELECT DEPARTMENT_ID
    FROM EMPLOYEE
    WHERE NAME = 'ELICE'
);
```

### 🔍쉬운설명

단일 행 서브쿼리는 이름 그대로 **서브쿼리가 딱 한 개의 결과(행)만 반환할 때** 사용됩니다. 이 결과는 메인 쿼리에서 `=`나 `>` 같은 일반적인 비교 연산자를 사용해 다른 값과 비교될 수 있습니다. 예를 들어, "가장 나이가 많은 학생의 이름을 찾아라"라고 할 때, 서브쿼리가 가장 나이 많은 학생의 나이 하나만 반환하는 경우입니다. **만약 서브쿼리가 두 개 이상의 행을 반환하는데 단일 행 비교 연산자를 사용하면 오류가 발생**합니다.

---

### 다중 행 서브쿼리 (Multi Row Subquery)

**다중 행 서브쿼리**는 서브쿼리의 결과가 **두 개 이상 행을 반환**할 수 있으며, 다중 행 비교 연산자(`IN`, `ALL`, `ANY`, `EXISTS`)와 같이 사용됩니다.

다중 행 서브쿼리 연산자:

- **`IN`**: 서브쿼리 결과에 존재하는 값들 중 하나라도 일치해야 합니다.
- **`EXISTS`**: 서브쿼리 결과 값이 존재하는지 여부를 확인합니다.
- **`ALL`**: 서브쿼리 결과에 존재하는 모든 값에 대해 조건을 만족해야 합니다.
- **`ANY`**: 서브쿼리 결과에 존재하는 값들 중 조건을 만족하는 것이 하나 이상 존재해야 합니다.

예시 (`IN`): 영업 또는 개발 팀에 속하는 직원들을 출력

```sql
SELECT NAME
FROM EMPLOYEE
WHERE DEPARTMENT_ID IN (
    SELECT ID
    FROM DEPARTMENT
    WHERE NAME = '품질' OR NAME = '영업'
);
```

### 🔍쉬운설명

다중 행 서브쿼리는 **서브쿼리가 여러 개의 결과(행)를 반환할 때** 사용됩니다. 일반적인 `=` 같은 비교 연산자는 여러 값과 동시에 비교할 수 없으므로, `IN`, `ALL`, `ANY`, `EXISTS`와 같은 **특별한 연산자를 사용**해야 합니다. 예를 들어, "특정 과목들을 수강한 모든 학생을 찾아라"라고 할 때, 서브쿼리가 여러 과목 `ID`를 반환하는 경우입니다.

- **`IN`**: "목록 안에 있으면 돼!"라고 생각하면 쉽습니다. `DEPARTMENT_ID IN (1, 2, 3)`은 `DEPARTMENT_ID`가 1, 2, 3 중 하나라도 있으면 된다는 의미입니다.
- **`EXISTS`**: "조건을 만족하는 결과가 하나라도 있으면 참!"입니다. 서브쿼리가 빈 결과를 반환하지 않으면 참이 됩니다.
- **`ALL`**: "모든 조건이 참이어야 해!"라고 이해할 수 있습니다. 예를 들어, `SALARY > ALL (100, 200, 300)`은 `SALARY`가 100보다 크고, 200보다 크고, 300보다 커야 한다는 의미, 즉 **`SALARY`가 서브쿼리 결과의 최댓값보다 커야 합니다**.
- **`ANY`**: "어떤 조건이든 하나만 참이면 돼!"입니다. 예를 들어, `SALARY > ANY (100, 200, 300)`은 `SALARY`가 100보다 크거나, 200보다 크거나, 300보다 크거나 (셋 중 하나만 만족하면) 된다는 의미, 즉 **`SALARY`가 서브쿼리 결과의 최솟값보다 크면 됩니다**.

예시 (`EXISTS`): 급여가 10000을 넘는 직원이 존재하는 부서에 소속된 모든 직원 출력

```sql
SELECT NAME
FROM EMPLOYEE A
WHERE EXISTS (
    SELECT ID
    FROM EMPLOYEE B
    WHERE B.SALARY >= 10000
    AND A.DEPARTMENT_ID = B.DEPARTMENT_ID
);
```

### 🔍쉬운설명

이 쿼리는 **급여가 10000 이상인 직원이 한 명이라도 있는 부서에 속한 모든 직원의 이름**을 찾습니다. 여기서 `EXISTS`는 서브쿼리가 어떤 행이라도 반환하면 `TRUE`를 반환하고, 아무것도 반환하지 않으면 `FALSE`를 반환합니다. 즉, 특정 부서(`A.DEPARTMENT_ID`) 내에 급여 10000 이상인 직원이 있는지 없는지만 확인합니다. 이 경우 실제 급여 값을 비교하는 것이 아니라, **존재 여부만 확인**하므로 효율적입니다.

예시 (`ALL`): 개발 팀 소속 모든 직원들 급여보다 급여가 큰 직원들 출력

```sql
SELECT NAME
FROM EMPLOYEE
WHERE SALARY >= ALL (
    SELECT SALARY
    FROM EMPLOYEE
    WHERE DEPARTMENT_ID = 1
);
```

### 🔍쉬운설명

이 쿼리는 **개발 팀(`DEPARTMENT_ID = 1`)에 속한 모든 직원의 급여보다 급여가 같거나 더 많은 직원**을 찾습니다. `ALL` 연산자는 서브쿼리가 반환하는 모든 값(여기서는 개발 팀 직원들의 급여 리스트)과 메인 쿼리의 조건(`SALARY >=`)을 각각 비교하여, **모든 비교가 `TRUE`일 때만 전체 조건이 `TRUE`** 가 됩니다. 즉, 현재 직원의 급여가 **개발 팀에서 가장 높은 급여보다도 같거나 많아야** 합니다.

예시 (`ANY`): 개발 팀 소속 임의의 직원들 급여보다 급여가 큰 직원들 출력

```sql
SELECT NAME
FROM EMPLOYEE
WHERE SALARY >= ANY (
    SELECT SALARY
    FROM EMPLOYEE
    WHERE DEPARTMENT_ID = 1
);
```

### 🔍쉬운설명

이 쿼리는 **개발 팀(`DEPARTMENT_ID = 1`)에 속한 어떤 직원의 급여보다 급여가 같거나 더 많은 직원**을 찾습니다. `ANY` 연산자는 서브쿼리가 반환하는 값들 중 **하나라도 메인 쿼리의 조건(`SALARY >=`)을 만족하면 전체 조건이 `TRUE`** 가 됩니다. 즉, 현재 직원의 급여가 **개발 팀에서 가장 낮은 급여보다 같거나 많으면** 됩니다.

---

### 다중 컬럼 서브쿼리 (Multi Column Subquery)

**다중 컬럼 서브쿼리**는 서브쿼리의 결과가 **여러 개의 컬럼을 반환**하며, 메인 쿼리의 조건과 동시에 비교됩니다.

예시: 각 부서에서 가장 높은 급여를 받는 직원의 이름과 급여 출력

```sql
SELECT NAME, SALARY
FROM EMPLOYEE
WHERE (DEPARTMENT_ID, SALARY) IN (
    SELECT DEPARTMENT_ID, MAX(SALARY)
    FROM EMPLOYEE
    GROUP BY DEPARTMENT_ID
);
```

### 🔍쉬운설명

다중 컬럼 서브쿼리는 **서브쿼리가 여러 개의 컬럼을 한 쌍으로 묶어서 반환**하고, 메인 쿼리도 이 여러 컬럼 쌍과 동시에 비교할 때 사용됩니다. 예를 들어, "같은 반에서 가장 높은 점수를 받은 학생들을 찾아라"라고 할 때, `(반, 최고 점수)`라는 두 개의 정보를 묶어서 비교하는 것과 같습니다. 위 예시에서는 각 부서의 `ID`와 해당 부서의 최고 급여를 한 쌍(`(DEPARTMENT_ID, MAX(SALARY))`)으로 묶어 서브쿼리에서 반환하고, 메인 쿼리에서는 이 쌍을 기준으로 직원을 찾습니다.

---

## 3. 스칼라 서브쿼리

**스칼라 서브쿼리**는 **하나의 속성을 가지면서 하나의 행만을 반환**하는 쿼리입니다. 이는 `SELECT`, `WHERE`, `HAVING` 절 등에서 사용할 수 있습니다.

예시 1: 부서명과 부서의 구성원 수를 출력하는 경우

```sql
SELECT NAME,
       (SELECT COUNT(*)
        FROM EMPLOYEE E
        WHERE E.DEPARTMENT_ID = D.ID)
FROM DEPARTMENT D;
```

### 🔍쉬운설명

스칼라 서브쿼리는 쿼리의 결과가 **단일 값, 즉 스칼라(Scalar) 값 하나만 반환**하는 서브쿼리입니다. 이 스칼라 값은 마치 일반적인 컬럼처럼 `SELECT` 절에 포함되거나, `WHERE` 또는 `HAVING` 절에서 조건을 비교하는 데 사용될 수 있습니다. 위 예시에서는 `DEPARTMENT` 테이블의 각 부서(`D`)에 대해, 해당 부서에 속한 직원들의 수(`COUNT(*)`)를 스칼라 서브쿼리로 계산하여 `NAME` 컬럼 옆에 출력합니다. 각 부서별로 직원의 수를 직접 계산하여 보여주는 효율적인 방법입니다.

---

스칼라 서브쿼리 예시 - `DUAL`

`FROM` 절을 사용하지 않고 특정 테이블 참조 없이 쿼리를 작성하는 경우도 있습니다. 예를 들어, 전체 임직원 중 팀장 직급이 차지하는 비율을 출력할 수 있습니다.

```sql
SELECT (SELECT COUNT(*) FROM EMPLOYEE WHERE DEPARTMENT_ID = 1)
       /
       (SELECT COUNT(*) FROM EMPLOYEE)
       AS DEVELOPER_RATIO
FROM DUAL;
```

### 🔍쉬운설명

**`DUAL` 테이블**은 오라클 데이터베이스에서 제공하는 특별한 더미 테이블로, 단일 행과 단일 컬럼을 가집니다. 주로 **테이블을 참조하지 않고 간단한 계산이나 시스템 함수의 결과를 확인**하고 싶을 때 사용됩니다. 위 예시에서는 전체 직원 수 대비 `DEPARTMENT_ID = 1`인 (예: 개발팀) 직원의 비율을 계산하기 위해 두 개의 스칼라 서브쿼리를 사용하고, 이 계산 결과를 `DUAL` 테이블을 통해 얻어냅니다. 이는 어떤 특정 테이블의 데이터를 조회하는 것이 아니라, **단순히 값을 계산하여 출력할 때 유용**합니다.

---

## 4. 뷰(View)

### VIEW

**뷰(View)** 는 다른 테이블에서 파생된 **가상의 테이블**입니다. 물리적으로 데이터가 저장되는 것이 아니라, **논리적으로만 존재**하며 뷰를 사용한 질의 시에는 DBMS에서 뷰 정의에 따라 질의를 재작성하여 수행합니다.

### 🔍쉬운설명

뷰는 실제 데이터가 저장되는 테이블이 아니라, **"미리 정의된 쿼리"** 라고 생각할 수 있습니다. 예를 들어, "모든 학생의 이름, 학과, 평균 점수"를 자주 조회한다고 가정해 봅시다. 이 정보를 얻기 위해서는 여러 테이블을 조인하고 계산해야 할 수 있습니다. 매번 복잡한 쿼리를 작성하는 대신, 이 쿼리 자체를 `STUDENT_SUMMARY`라는 뷰로 저장해 두면, 나중에는 `SELECT * FROM STUDENT_SUMMARY;`와 같이 간단하게 조회할 수 있습니다. 뷰를 조회할 때마다 데이터베이스 시스템은 뷰에 정의된 원래의 복잡한 쿼리를 다시 실행하여 **최신 데이터를 보여줍니다**.

---

### VIEW의 장점

**독립성**: 테이블 구조가 변경되어도 뷰를 사용하는 응용 프로그램은 변경하지 않아도 됩니다.

**편리성**: 자주 사용되는 복잡한 쿼리를 미리 뷰로 정의해 놓으면, 추후 쿼리는 간단한 형태로 표현할 수 있습니다.

**보안성**: 사용자의 권한에 따라 열람 가능한 데이터를 다르게 할 수 있습니다. 권한에 따라 확인 가능한 컬럼을 정의하여 뷰를 생성하면, 기본 테이블 노출 없이 접근 제어를 할 수 있습니다.

### 🔍쉬운설명

뷰는 데이터베이스를 더 사용하기 쉽고 안전하게 만드는 여러 가지 장점을 가집니다.

**독립성**: 만약 실제 테이블의 컬럼 이름이 바뀌거나 구조가 변경되어도, 뷰를 중간에 두면 응용 프로그램은 뷰만 바라보고 있기 때문에 테이블 변경의 영향을 받지 않습니다. 뷰 정의만 수정하면 됩니다.

**편리성**: 복잡한 조인이나 조건이 들어간 쿼리를 매번 새로 작성하는 것은 번거롭습니다. 뷰로 만들어두면, 마치 하나의 테이블처럼 간단하게 `SELECT` 문을 사용할 수 있어 쿼리 작성이 훨씬 편리해집니다.

**보안성**: 모든 직원에게 모든 정보를 보여줄 필요는 없을 때 뷰가 유용합니다. 예를 들어, 인사팀 직원에게는 모든 정보를 보여주는 뷰를, 일반 직원에게는 급여 정보가 제외된 뷰를 제공하여 접근 권한을 세밀하게 제어할 수 있습니다. 실제 테이블을 직접 노출하지 않고 필요한 정보만 선별적으로 보여주기 때문에 **보안이 강화**됩니다.

---

### VIEW의 특징

- **생성된 뷰는 또 다른 뷰를 생성하는 데 사용**될 수 있습니다.
- **뷰의 정의는 변경할 수 없으며**, 삭제 후 재생성이 필요합니다.
- **뷰를 통한 갱신에는 제약이 따릅니다**. 갱신을 위해서는 기본적으로 원천 테이블의 기본키가 포함되어야 합니다.
- **원천이 되는 테이블이나 뷰가 삭제되면 이를 기반으로 하는 뷰도 함께 삭제**됩니다.

### 🔍쉬운설명

뷰는 편리하지만 몇 가지 알아둘 점들이 있습니다.

**뷰 위의 뷰**: 하나의 뷰를 만들고, 그 뷰를 바탕으로 또 다른 뷰를 만들 수 있습니다. 마치 피라미드처럼 여러 층의 뷰를 구성하여 데이터를 더 추상화할 수 있습니다.

**정의 변경 불가**: 뷰를 만들 때 정한 쿼리(`SELECT` 문)는 나중에 직접 수정할 수 없습니다. 만약 뷰의 내용을 바꾸고 싶다면, **기존 뷰를 삭제하고 새로운 쿼리로 다시 생성**해야 합니다.

**갱신 제약**: 뷰를 통해서 원본 테이블의 데이터를 갱신(`INSERT`, `UPDATE`, `DELETE`)하는 것을 갱신(Update)이라고 합니다. 하지만 **모든 뷰가 갱신 가능한 것은 아닙니다**. 특히 여러 테이블을 조인해서 만든 뷰나, 그룹 함수(`COUNT`, `SUM` 등)를 사용한 뷰는 갱신하기 어렵거나 불가능합니다. 갱신하려면 원본 테이블의 고유한 레코드를 식별할 수 있는 **기본키 정보가 뷰에 포함**되어야 하는 등 특정 조건들을 만족해야 합니다.

**종속성**: 뷰는 원본 테이블이나 다른 뷰에 의존합니다. 만약 원본 테이블이나 뷰가 사라지면, 그 위에 만들어진 뷰들도 더 이상 작동하지 못하고 **함께 사라지게** 됩니다.

---

### VIEW 정의 쿼리

뷰는 **`CREATE VIEW`** 문을 사용하여 정의합니다. `OR REPLACE` 옵션을 사용하면 같은 이름의 뷰가 존재할 경우 기존 뷰를 무시하고 대체합니다.

```sql
CREATE [OR REPLACE] VIEW view_name AS
SELECT column1, column2, ...
FROM table_name
WHERE condition;
```

예시: EMPLOYEE와 DEPARTMENT 테이블을 조인하여 전체 직원 정보를 담은 `EMPLOYEE_FULL` 뷰 생성

```sql
CREATE VIEW EMPLOYEE_FULL AS (
    SELECT
        E.ID AS EMPLOYEE_ID,
        E.NAME AS EMPLOYEE_NAME,
        E.SALARY,
        E.DEPARTMENT_ID,
        D.NAME AS DEPARTMENT_NAME
    FROM EMPLOYEE E
    LEFT OUTER JOIN DEPARTMENT D
    ON E.DEPARTMENT_ID = D.ID
);
```

생성된 뷰는 다음과 같이 조회할 수 있습니다.

```sql
SELECT * FROM EMPLOYEE_FULL;
```

### 🔍쉬운설명

뷰를 만드는 방법은 간단합니다. `CREATE VIEW` 다음에 만들 뷰의 이름을 쓰고, `AS` 뒤에 뷰가 어떤 데이터를 보여줄 것인지 정의하는 `SELECT` 쿼리를 작성하면 됩니다.

위 예시에서는 `EMPLOYEE` 테이블과 `DEPARTMENT` 테이블을 `LEFT OUTER JOIN`하여, 직원 `ID`, 이름, 급여, 부서 `ID`, 부서 이름을 포함하는 가상의 테이블 `EMPLOYEE_FULL`을 만들었습니다. 이제 이 `EMPLOYEE_FULL` 뷰는 실제 테이블처럼 `SELECT * FROM EMPLOYEE_FULL;`과 같이 간단하게 조회할 수 있으며, 이 쿼리를 실행하면 데이터베이스는 뷰 정의에 있는 복잡한 JOIN 쿼리를 실행하여 결과를 보여줍니다.

- `CREATE VIEW view_name AS SELECT ...`: `view_name`이라는 이름의 뷰를 `SELECT ...` 쿼리 결과로 만듭니다.
- `OR REPLACE`: 만약 `view_name`이라는 뷰가 이미 존재한다면, 에러를 내지 않고 **기존 뷰를 새로운 정의로 덮어씌웁니다**. 뷰의 정의를 변경하고 싶을 때 유용합니다.
