# SQL 함수 & 다수의 테이블 제어하기 & 서브쿼리


# 📘  1. SQL 요약 함수

SQL을 사용하여 데이터를 효과적으로 다루는 방법을 설명하며, 특히 데이터의 개수, 제한, 합계, 평균, 최댓값, 최솟값을 구하는 **내장 함수 사용법**에 중점을 둡니다.

---

## 01. COUNT

### COUNT 함수

`COUNT`는 검색 결과 데이터의 **개수를 가져오는 내장 함수**입니다. **`NULL`인 데이터는 결과에서 제외**됩니다.

### 🔍쉬운설명

`COUNT` 함수는 마치 "이 테이블에 몇 개의 행이 들어있지?" 또는 "이 컬럼에 비어있지 않은 값이 몇 개 있지?" 하고 세어보는 것과 같아요.

예를 들어, 도서관 책이 몇 권인지 알고 싶을 때 (`id` 컬럼으로 세면) `COUNT(id)`를 사용하고, 모든 데이터의 개수를 알고 싶을 때는 `COUNT(*)`를 사용합니다.

예시: `book` 테이블에 3권의 책이 있다면 `COUNT(id)`의 결과는 `3`이 됩니다. 만약 어떤 책의 `author` 컬럼이 비어있다면 `COUNT(author)`를 했을 때 그 책은 세지않아요.

---

## 02. LIMIT

### LIMIT 명령

**`LIMIT`는 테이블에서 출력하고자 하는 데이터의 개수를 제한하는 명령**입니다.

### 🔍쉬운설명

`LIMIT`는 "너무 많은 데이터를 한 번에 보고 싶지 않아! 딱 몇 개만 보여줘!" 할 때 사용하는 명령이에요. 예를 들어, 도서관에 있는 모든 책 목록 대신 최신 3권만 보고 싶을때 유용하죠.

기본 문법:
- `LIMIT 5;` : 위에서부터 **5개**의 데이터를 가져옵니다.
- `LIMIT 1, 5;` : **2번째 데이터부터 5개**의 데이터를 가져옵니다. 여기서 첫 번째 컬럼의 시작은 `0`입니다.

즉, **`LIMIT A, B`는 A번째 데이터부터 B개의 데이터를 가져온다**는 의미예요 (`0`부터 시작하므로 A는 **offset**을 의미합니다).

---

## 03. SUM & AVG

### SUM 함수

**`SUM`은 지정한 컬럼들의 값을 모두 더하여 총점을 구해주는 내장 함수**입니다.

### 🔍쉬운설명

`SUM`은 합계를 구할 때 사용하는 함수예요. 예를 들어, 학생들의 중간고사 수학 점수 총합을 알고 싶을 때 일일이 계산하는 대신 `SUM(math)`처럼 사용할 수 있습니다.

예시: `grade` 테이블에 있는 `math` 점수를 모두 더하면 `SUM(math)`는 `220`을 반환합니다.

---

### AVG 함수

**`AVG`는 지정한 컬럼들의 평균값을 구해주는 내장 함수**입니다.

### 🔍쉬운설명

`AVG`는 평균을 구할 때 사용하는 함수예요. `SUM`과 `COUNT`를 따로 사용하지 않고도 쉽게 평균을 구할 수 있죠. 예를 들어, 학생들의 국어, 영어, 수학 과목별 평균 점수를 알고 싶을 때 `AVG(korean)`, `AVG(english)`, `AVG(math)`를 사용할 수 있습니다.

예시: `grade` 테이블에서 `korean` 점수 평균은 `96.6667`, `english`는 `73.3333`, `math`는 `73.3333`이 됩니다.

---

## 04. MAX & MIN

### MAX 함수

**`MAX`는 테이블에 존재하는 데이터에서 최댓값을 가져오는 내장 함수**입니다. **숫자형뿐만 아니라 문자형 데이터에서도 사용 가능**합니다.

### 🔍쉬운설명

`MAX`는 "이 컬럼에서 가장 큰 값이 뭐야?" 하고 찾을 때 사용하는 함수예요. 예를 들어, 학생들 국어 점수 중에 최고점을 찾고 싶다면 `MAX(korean)`을 사용합니다.

예시: `grade` 테이블에서 `korean` 점수의 최댓값은 `100`입니다. 문자형 데이터도 사전순으로 가장 큰 값을 찾을 수 있습니다.

---

### MIN 함수

**`MIN`은 테이블에 존재하는 데이터에서 최솟값을 가져오는 함수**입니다. **숫자형뿐만 아니라 문자형 데이터에서도 사용 가능**합니다.

### 🔍쉬운설명

`MIN`은 "이 컬럼에서 가장 작은 값이 뭐야?" 하고 찾을 때 사용하는 함수예요. 예를 들어, 학생들 영어 점수 중에 최저점을 찾고 싶다면 `MIN(english)`를 사용합니다.

예시: `grade` 테이블에서 `english` 점수의 최솟값은 `50`입니다. `MAX`와 마찬가지로 문자형 데이터도 사전순으로 가장 작은 값을 찾을 수 있습니다.

# 📘 2 .다수의 테이블 제어하기

이 자료는 SQL을 사용하여 데이터를 효율적으로 그룹화하고 여러 테이블을 조인하여 조회하는 방법을 다룹니다. **`GROUP BY`**, **`HAVING`**, **`INNER JOIN`**, **`LEFT JOIN`**, **`RIGHT JOIN`** 등 SQL의 핵심 기능들을 학습하여 복잡한 데이터 분석 및 관리를 수행할 수 있도록 돕습니다.

---

## 데이터 그룹 짓기

데이터 그룹화는 특정 기준으로 데이터를 묶어 **통계 정보(합계, 평균, 개수, 최대값, 최소값 등)를 얻는 과정**입니다. **`GROUP BY`** 절을 사용하여 특정 컬럼을 기준으로 데이터를 그룹화하고, `SUM`, `AVG`, `COUNT`, `MAX`, `MIN`과 같은 그룹 함수를 활용하여 그룹별 집계 결과를 얻을 수 있습니다.

### 🔍쉬운설명

데이터 그룹 짓기란 무엇일까요? 우리가 어떤 데이터를 볼 때, 그냥 쭉 나열된 것보다는 어떤 기준에 따라 묶어서 보는 게 편할 때가 많아요. 예를 들어, 도서관에서 회원들이 책을 얼마나 빌려갔는지 알고 싶을 때, 모든 대여 기록을 하나씩 보는 대신 '회원별'로 묶어서 각 회원이 총 몇 권을 빌려갔는지 숫자를 세어보는 것이죠. 이것이 바로 데이터 그룹 짓기입니다!

어떻게 그룹을 지을까요? SQL에서는 **`GROUP BY [컬럼명]`** 이렇게 사용하면, 해당 컬럼의 값이 같은 데이터끼리 묶이게 됩니다.

예를 들어, `rental` 테이블에 `user_id`, `book_id` 등의 대여 기록이 있다고 해봅시다.

| rental_id | user_id | book_id |
|-----------|---------|---------|
| 1 | 1 | 1000 |
| 2 | 1 | 1001 |
| 3 | 3 | 1004 |

`user_id`를 기준으로 그룹을 짓고 싶다면 이렇게 명령을 내려요.

```sql
SELECT user_id, COUNT(*)
FROM rental
GROUP BY user_id;
```

이 SQL 문은 "`rental` 테이블에서 `user_id` 별로 그룹을 만들고, 각 그룹에 속한 행의 개수를 세어라"는 의미가 됩니다.

결과:

| user_id | COUNT(*) |
|---------|----------|
| 1 | 2 |
| 3 | 1 |

이 결과를 보면, `user_id`가 `1`인 회원은 책을 2번 빌렸고, `user_id`가 `3`인 회원은 책을 1번 빌렸다는 것을 알 수 있습니다.

**✨ 그룹함수와 함께 사용하기 (`SUM`, `AVG`, `COUNT`, `MAX`, `MIN`)**

`GROUP BY`는 혼자서도 쓰이지만, 보통은 `SUM`(합계), `AVG`(평균), `COUNT`(개수), `MAX`(최대값), `MIN`(최소값) 같은 **그룹 함수와 함께 사용될 때 강력해져요.**

- **`SUM(컬럼명)`** : 특정 그룹 내 해당 컬럼 값들의 총합을 계산해요. 예를 들어, **총 대여료**를 계산할 때 쓸 수 있겠죠.
- **`AVG(컬럼명)`** : 특정 그룹 내 해당 컬럼 값들의 평균을 계산해요. **평균 대여 기간** 같은 것을 구할 때 유용해요.
- **`COUNT(컬럼명)` 또는 `COUNT(*)`** : 특정 그룹 내 행의 개수를 세어요. 위 예시처럼 `user_id`별 대여 횟수를 셀 때 `COUNT(*)`를 사용했어요.
- **`MAX(컬럼명)`** : 특정 그룹 내 해당 컬럼 값 중 가장 큰 값을 찾아요. **가장 비싼 책의 가격**을 찾을 때요.
- **`MIN(컬럼명)`** : 특정 그룹 내 해당 컬럼 값 중 가장 작은 값을 찾아요. **가장 저렴한 책의 가격**을 찾을 때요.

이 함수들을 사용하면 각 그룹에 대한 다양한 통계 정보를 한눈에 파악할 수 있어서 데이터 분석에 아주 큰 도움이 됩니다!

---

## 데이터 그룹에 조건 적용하기

`GROUP BY` 절로 그룹화된 결과에 조건을 적용하려면 **`HAVING` 절**을 사용합니다. **`WHERE` 절은 그룹화 전에 개별 행에 조건을 적용**하지만, **`HAVING` 절은 그룹 함수를 통해 집계된 결과에 조건을 적용**할 때 사용합니다. 예를 들어, 특정 회원들이 책을 2번 이상 대여했는지 조회할 때 `HAVING COUNT(user_id) > 1`과 같이 사용할 수 있습니다.

### 🔍쉬운설명

데이터 그룹에 조건을 거는 이유? 이전 섹션에서 우리는 회원별로 책 대여 횟수를 그룹화해서 알아보는 방법을 배웠어요. 그런데 만약 "책을 2번 이상 빌려간 회원들만 보고 싶다"와 같은 더 구체적인 조건을 추가하고 싶다면 어떻게 해야 할까요? 이럴 때 **`HAVING` 절**이 필요합니다.

**`WHERE` vs `HAVING` : 무엇이 다를까요?**

- **`WHERE` 절** : `GROUP BY` 이전에 개별 행에 조건을 적용해서, 조건을 만족하는 행들만 추려낸 다음 그룹화를 진행합니다. 즉, 원본 데이터에서 특정 조건을 만족하는 '개별 데이터'를 필터링할 때 사용해요.
- **`HAVING` 절** : `GROUP BY` 이후에, 즉 이미 그룹화되고 `COUNT`, `SUM` 등 그룹 함수로 집계된 '그룹 결과'에 조건을 적용할 때 사용합니다.

예를 들어, `rental` 테이블에서 `user_id`별 대여 횟수를 세고, 그중에서 대여 횟수가 `1`을 초과하는(즉, 2번 이상 빌린) 회원들만 보고 싶다면 다음과 같이 SQL 문을 작성합니다.

```sql
SELECT user_id, COUNT(user_id)
FROM rental
GROUP BY user_id
HAVING COUNT(user_id) > 1;
```

여기서 **`COUNT(user_id) > 1`은 각 `user_id` 그룹의 대여 횟수(그룹 함수 `COUNT`의 결과)가 `1`을 초과하는지에 대한 조건**입니다.

`rental` 테이블이 다음과 같다고 할 때:

| rental_id | user_id | book_id |
|-----------|---------|---------|
| 1 | 1 | 1000 |
| 2 | 1 | 1001 |
| 3 | 3 | 1004 |

`GROUP BY user_id`를 하면 `user_id=1`은 2개, `user_id=3`은 1개로 그룹화됩니다. 이후 `HAVING COUNT(user_id) > 1` 조건을 적용하면 `user_id=1` 그룹만 조건을 만족하므로 최종 결과는 다음과 같습니다.

| user_id | COUNT(*) |
|---------|----------|
| 1 | 2 |

이처럼 `HAVING` 절을 사용하면 **그룹별 통계 결과에 대해 세밀한 필터링이 가능**해져서, 데이터 분석의 깊이를 더할 수 있습니다.

## 두 개의 테이블에서 조회하기

여러 테이블에 분산된 정보를 한 번에 조회하기 위해 **`INNER JOIN`** 을 사용합니다. `INNER JOIN`은 두 테이블에서 **공통된 값이 있는 행들만 연결**하여 보여줍니다. 예를 들어, `rental` 테이블의 `user_id`와 `user` 테이블의 `id`가 일치하는 경우에만 정보를 함께 조회할 수 있습니다.

### 🔍쉬운설명

왜 여러 테이블에서 조회해야 할까요? 데이터베이스는 효율적인 관리를 위해 정보를 여러 개의 작은 테이블로 나누어 저장하는 경우가 많습니다. 예를 들어, '회원 정보'는 `user` 테이블에, '책 대여 기록'은 `rental` 테이블에 저장될 수 있어요.

그런데 만약 "어떤 회원이 어떤 책을 빌려갔는지" 한눈에 보고 싶다면, 이 두 테이블의 정보가 필요하겠죠? 이럴 때 **`JOIN`** 을 사용합니다.

**`INNER JOIN`의 기본 개념** — `INNER JOIN`은 두 테이블에서 **서로 공통된 부분만 합쳐서 보여주는 방식**입니다. 마치 두 개의 원이 겹쳐지는 부분처럼, 두 테이블에 모두 존재하는 데이터(`user_id`와 `id`가 일치하는 경우)만을 결과로 반환해요.

예시:

`user` 테이블:

| id | name | email |
|----|------|-------|
| 1 | chanhwan | choich@elice.com |
| 2 | haesol | sunsol@elice.com |
| 3 | hyungon | gone@elice.com |

`rental` 테이블:

| rental_id | user_id | book_id |
|-----------|---------|---------|
| 1 | 1 | 1000 |
| 2 | 1 | 1001 |
| 3 | 3 | 1004 |

`user_id`와 `id`가 같은 행을 연결한다고 가정해봅시다. `user` 테이블에는 `id`가 `2`인 `'haesol'`이 있지만, `rental` 테이블에는 `user_id`가 `2`인 대여 기록이 없습니다. 반대로, `rental` 테이블에만 있는 `user_id`가 `4`인 대여 기록도 있을 수 있죠(이 예시에서는 없지만요). **`INNER JOIN`은 이 경우 `'haesol'`의 정보나 `user_id`가 `4`인 대여기록은 결과에 포함하지 않습니다.**

기본 문법:

```sql
SELECT *
FROM rental
INNER JOIN user;
```

이 명령어는 `rental` 테이블과 `user` 테이블을 `INNER JOIN` 하되, 어떤 컬럼을 기준으로 합칠지 명시하지 않았기 때문에 SQL 엔진이 최적의 조인 조건을 찾아 연결을 시도합니다. 하지만 **명확한 조인을 위해서는 다음 섹션에서 배울 `ON` 절을 사용하는 것이 일반적**입니다.

`INNER JOIN`을 사용하면 여러 테이블에 흩어진 정보를 하나의 결과 집합으로 모아서 볼 수 있어 데이터 탐색과 분석이 훨씬 수월해집니다.

---

## 조건을 적용해 두 개의 테이블 조회하기

`INNER JOIN`을 통해 두 테이블을 연결할 때, **어떤 컬럼을 기준으로 연결할 것인지 명시하기 위해 `ON` 절을 사용**합니다. `ON` 절에 `user.id = rental.user_id`와 같이 조건을 지정하여 두 테이블의 `id`와 `user_id`가 일치하는 경우에만 레코드를 연결할 수 있습니다. **`테이블이름.컬럼명`** 형태로 컬럼을 명시하여 모호함을 방지합니다.

### 🔍쉬운설명

`JOIN`에 조건이 필요한 이유 — 지난 섹션에서 `INNER JOIN`으로 두 테이블을 합칠 수 있다는 것을 배웠습니다. 하지만 "어떤 기준으로 두 테이블을 연결해야 할지" 명확히 알려주지 않으면 데이터베이스가 제대로 연결하지 못하거나, 원치 않는 결과를 내놓을 수 있어요. 이 문제를 해결하기 위해 **`ON` 절**을 사용합니다.

**`ON` 절을 이용한 `INNER JOIN`** — `ON` 절은 `INNER JOIN`을 할 때, 두 테이블의 어떤 컬럼들을 서로 일치시켜 연결할 것인지 조건을 명시하는 역할을 합니다. 보통은 두 테이블 간의 **기본 키(Primary Key)** 와 **외래 키(Foreign Key)** 관계를 사용하여 연결합니다.

예시: `user` 테이블의 `id` 컬럼과 `rental` 테이블의 `user_id` 컬럼을 기준으로 연결하고 싶다면 다음과 같이 `ON` 절을 사용합니다.

```sql
SELECT *
FROM rental
INNER JOIN user
ON user.id = rental.user_id;
```

- **`SELECT *`** : 두 테이블의 모든 컬럼을 조회합니다.
- **`FROM rental`** : `rental` 테이블을 기본으로 합니다.
- **`INNER JOIN user`** : `user` 테이블과 내부 조인합니다.
- **`ON user.id = rental.user_id`** : `user` 테이블의 `id` 컬럼과 `rental` 테이블의 `user_id` 컬럼의 값이 같을 때만 두 테이블의 행을 연결합니다.

결과 확인: `user` 테이블과 `rental` 테이블을 `user.id = rental.user_id` 조건으로 `INNER JOIN`하면 다음과 같은 결과가 나옵니다.

| rental_id | user_id | book_id | name | email |
|-----------|---------|---------|------|-------|
| 1 | 1 | 1000 | chanhwan | choich@elice.com |
| 2 | 1 | 1001 | chanhwan | choich@elice.com |
| 3 | 3 | 1004 | hyungon | gone@elice.com |

이 결과에서 `user_id`가 `2`인 `'haesol'`의 정보는 `rental` 테이블에 해당하는 대여 기록이 없기 때문에 나타나지 않습니다. **`INNER JOIN`은 양쪽 테이블 모두에 매칭되는 데이터가 있을 때만 결과를 보여주기 때문**이죠.

**`테이블이름.컬럼명` 사용** : `ON` 절에서는 `user.id`나 `rental.user_id`처럼 **`테이블이름.컬럼명`** 형태로 컬럼을 명확히 지정하는 것이 중요합니다. 이는 여러 테이블에 동일한 이름의 컬럼이 있을 때 어떤 테이블의 컬럼을 참조하는지 명확히 하여 혼동을 피하고 오류를 방지하기 위함입니다.

---

## LEFT JOIN

**`LEFT JOIN`은 `INNER JOIN`과 달리, 조인의 기준이 되는 왼쪽 테이블의 모든 레코드를 포함하여 결과를 반환**합니다. 오른쪽 테이블에서 매칭되는 레코드가 없는 경우, 해당 컬럼의 값은 **`NULL`로 채워**집니다. 이는 왼쪽 테이블의 모든 데이터를 유지하면서 오른쪽 테이블의 관련 정보를 함께 보고 싶을 때 유용합니다.

### 🔍쉬운설명

`LEFT JOIN`이 필요한 상황 — `INNER JOIN`은 두 테이블에 모두 일치하는 데이터만 보여주었죠. 그런데 만약 "모든 회원 정보를 보고 싶은데, 혹시 책을 빌린 기록이 있다면 그 기록도 함께 보여줘"와 같은 요청이 있다면 어떻게 할까요? 즉, **왼쪽의 데이터는 모두 보여주면서, 오른쪽 테이블에 매칭되는 데이터가 없어도 왼쪽 테이블의 데이터는 사라지지 않게** 하고 싶을 때 **`LEFT JOIN`** 을 사용합니다.

**`LEFT JOIN`의 개념**

- **`LEFT JOIN`은 조인하는 두 테이블 중 왼쪽에 있는 테이블의 모든 레코드를 결과에 포함**합니다. `ON` 절의 조건에 따라:
- 만약 왼쪽 테이블의 레코드와 오른쪽 테이블의 레코드가 일치하면, 두 테이블의 컬럼 값들이 합쳐져서 하나의 행으로 표시됩니다.
- 만약 왼쪽 테이블의 레코드와 일치하는 오른쪽 테이블의 레코드가 없다면, 왼쪽 테이블의 레코드는 그대로 유지하고, 오른쪽 테이블의 컬럼 값들은 **`NULL`** 로 채워집니다.

예시: `user` 테이블(왼쪽 테이블)과 `rental` 테이블(오른쪽 테이블)이 다음과 같고, `user.id = rental.user_id` 조건으로 `LEFT JOIN`한다고 가정해봅시다.

`user` 테이블:

| id | name | email |
|----|------|-------|
| 1 | chanhwan | choich@elice.com |
| 2 | haesol | sunsol@elice.com |
| 3 | hyungon | gone@elice.com |

`rental` 테이블:

| rental_id | user_id | book_id |
|-----------|---------|---------|
| 1 | 1 | 1000 |
| 2 | 1 | 1001 |
| 3 | 3 | 1004 |

여기서 `id`가 `2`인 `'haesol'` 회원은 `rental` 테이블에 대여 기록이 없습니다. `INNER JOIN`이었다면 `'haesol'`의 정보는 결과에 포함되지 않았겠지만, **`LEFT JOIN`에서는 `'haesol'`의 정보도 함께 출력**됩니다.

기본 문법:

```sql
SELECT *
FROM user                   -- 왼쪽 테이블
LEFT JOIN rental            -- 오른쪽 테이블
ON user.id = rental.user_id;
```

결과:

| user_id | name | email | rental_id | book_id |
|---------|------|-------|-----------|---------|
| 1 | chanhwan | choich@elice.com | 1 | 1000 |
| 1 | chanhwan | choich@elice.com | 2 | 1001 |
| 2 | haesol | sunsol@elice.com | NULL | NULL |
| 3 | hyungon | gone@elice.com | 3 | 1004 |

결과에서 `'haesol'`의 `rental_id`와 `book_id`가 **`NULL`** 로 표시되는 것을 볼 수 있습니다. 이는 `'haesol'` 회원은 존재하지만, 해당 대여 기록은 없다는 것을 의미합니다.

**`INNER JOIN` vs `LEFT JOIN` 시각화:**
- **`INNER JOIN`** : 두 원이 겹치는 가운데 부분만 보여줍니다.
- **`LEFT JOIN`** : 왼쪽 원 전체와 두 원이 겹치는 부분을 보여줍니다.

이처럼 `LEFT JOIN`을 사용하면 기준이 되는 왼쪽 테이블의 모든 정보를 유지하면서 연관된 다른 테이블의 정보를 함께 조회할 수 있어, **특정 목록의 누락 없는 조회가 필요할 때 매우 유용**합니다!

---

## RIGHT JOIN

**`RIGHT JOIN`은 `LEFT JOIN`과 반대로, 조인의 기준이 되는 오른쪽 테이블의 모든 레코드를 포함하여 결과를 반환**합니다. 왼쪽 테이블에서 매칭되는 레코드가 없는 경우, 해당 컬럼의 값은 **`NULL`로 채워**집니다. 이는 오른쪽 테이블의 모든 데이터를 유지하면서 왼쪽 테이블의 관련 정보를 함께 보고 싶을 때 사용됩니다.

### 🔍쉬운설명

`RIGHT JOIN`이 필요한 상황 — `LEFT JOIN`이 왼쪽 테이블의 데이터를 기준으로 모든 정보를 보여주었다면, `RIGHT JOIN`은 그 반대입니다. "모든 대여 기록을 보고 싶은데, 혹시 대여한 회원의 정보가 있다면 함께 보여줘. 만약 회원 정보가 없어도 대여 기록은 놓치지 않고 보고 싶어"와 같은 요청이 있을 때 `RIGHT JOIN`을 사용합니다.

즉, **오른쪽 테이블의 데이터는 모두 보여주면서, 왼쪽 테이블에 매칭되는 데이터가 없어도 오른쪽 테이블의 데이터는 사라지지 않게** 하고 싶을 때 유용합니다.

**`RIGHT JOIN`의 개념** — `RIGHT JOIN`은 조인하는 두 테이블 중 **오른쪽에 있는 테이블의 모든 레코드를 결과에 포함**합니다. `ON` 절의 조건에 따라:
- 만약 오른쪽 테이블의 레코드와 왼쪽 테이블의 레코드가 일치하면, 두 테이블의 컬럼 값들이 합쳐져서 하나의 행으로 표시됩니다.
- 만약 오른쪽 테이블의 레코드와 일치하는 왼쪽 테이블의 레코드가 없다면, 오른쪽 테이블의 레코드는 그대로 유지하고, 왼쪽 테이블의 컬럼 값들은 **`NULL`** 로 채워집니다.

예시: `user` 테이블(왼쪽 테이블)과 `rental` 테이블(오른쪽 테이블)이 다음과 같고, `user.id = rental.user_id` 조건으로 `RIGHT JOIN`한다고 가정해봅시다.

`user` 테이블:

| id | name | email |
|----|------|-------|
| 1 | chanhwan | choich@elice.com |
| 2 | haesol | sunsol@elice.com |
| 3 | hyungon | gone@elice.com |

`rental` 테이블:

| rental_id | user_id | book_id |
|-----------|---------|---------|
| 1 | 1 | 1000 |
| 2 | 1 | 1001 |
| 3 | 3 | 1004 |
| 4 | 4 | (예시) |

여기서 `rental` 테이블에는 `user_id`가 `4`인 대여 기록이 있지만, `user` 테이블에는 `id`가 `4`인 회원이 없습니다. `LEFT JOIN`이나 `INNER JOIN`이었다면 이 대여 기록은 결과에 포함되지 않았겠지만, **`RIGHT JOIN`에서는 이 기록도 함께 출력**됩니다.

기본 문법:

```sql
SELECT *
FROM user                    -- 왼쪽 테이블
RIGHT JOIN rental            -- 오른쪽 테이블
ON user.id = rental.user_id;
```

결과:

| id | name | email | rental_id | book_id |
|----|------|-------|-----------|---------|
| 1 | chanhwan | choich@elice.com | 1 | 1000 |
| 1 | chanhwan | choich@elice.com | 2 | 1001 |
| NULL | NULL | NULL | 4 | 1004 |

결과에서 `rental_id`가 `4`인 대여 기록은 `user` 테이블에서 매칭되는 `id`가 없으므로 `id`, `name`, `email` 컬럼이 **`NULL`** 로 표시되는 것을 볼 수 있습니다.

**`LEFT JOIN` vs `RIGHT JOIN` 시각화:**
- **`LEFT JOIN`** : 왼쪽 원 전체와 두 원이 겹치는 부분을 보여줍니다.
- **`RIGHT JOIN`** : 오른쪽 원 전체와 두 원이 겹치는 부분을 보여줍니다.

`RIGHT JOIN`은 주로 **로그 데이터나 이벤트 기록처럼 특정 행동 기록이 중요**하고, 해당 행동을 수행한 주체(예: 회원)의 정보가 없을 수도 있는 경우에 유용하게 사용됩니다.

# 📘  3.  서브쿼리

이 자료는 SQL의 서브쿼리에 대해 정의하고, 반환되는 값의 수와 사용되는 위치에 따라 서브쿼리를 분류하여 설명합니다. 서브쿼리의 특징, 사용 예시 및 주의사항을 다루며, 효율적인 데이터 검색 방법을 제시합니다.

---

## 01. 서브쿼리

### 서브쿼리 정의

**서브쿼리는 하나의 쿼리 안에 포함된 또 다른 쿼리**를 의미합니다. **메인 쿼리가 서브쿼리를 포함하는 종속적인 관계**를 가집니다.

### 🔍쉬운설명

서브쿼리는 **"쿼리 안의 쿼리"** 라고 생각하면 쉬워요. 우리가 어떤 질문(메인 쿼리)을 했는데, 그 질문에 답하기 위해 먼저 다른 작은 질문(서브쿼리)을 해결해야 하는 상황과 비슷합니다. 예를 들어 "우리 회사에서 `'elice'`라는 이름을 가진 직원보다 급여를 많이 받는 사람을 찾아줘!"라는 질문을 한다고 가정해봅시다. 이때 `'elice'`의 급여가 얼마인지 먼저 알아야 하겠죠? 이 `'elice'`의 급여를 알아내는 부분이 바로 **서브쿼리**입니다. 이렇게 서브쿼리가 먼저 실행되어 메인 쿼리에 필요한 정보를 제공하는 **'종속적인'** 관계를 가집니다.

---

### 서브쿼리의 특징

- **알려지지 않은 기준을 이용한 검색에 유용**합니다.
- **메인 쿼리가 실행되기 이전에 한번만 실행**됩니다.
- **한 문장에서 여러 번 사용 가능**합니다.

### 🔍쉬운설명

서브쿼리의 가장 큰 특징은 **미리 알 수 없는 값을 기준으로 데이터를 찾을 때 아주 유용**하다는 점이에요. 예를 들어, 특정 직원의 급여를 정확히 모르는 상태에서도 '그 직원보다 급여가 많은 사람'을 찾을 수 있게 해줍니다. 또, 서브쿼리는 메인 쿼리가 실행되기 전에 딱 한번만 실행되어서 필요한 값을 미리 계산해 메인 쿼리에 전달합니다. 그리고 필요하다면 하나의 SQL 문장 안에서 서브쿼리를 여러 번 사용할 수도 있어요!

**기존의 검색 방법과 서브쿼리를 사용한 예시 비교**

기존 검색 방법:
```sql
SELECT * FROM employee
WHERE 급여 > 2500;
```
설명: 사원 `elice`의 급여가 `2500`인 것을 알고 있는 상태에서 더 높은 급여를 받는 사원을 조회합니다.

서브쿼리를 사용한 예시:
```sql
SELECT * FROM employee
WHERE 급여 > (SELECT 급여 FROM employee WHERE 이름 = 'elice');
```
설명: 사원 `elice`의 급여를 알지 못해도, 서브쿼리가 `elice`의 급여를 찾아내어 메인 쿼리에 전달함으로써 검색이 가능합니다.

### 🔍쉬운설명

위 예시를 보면 서브쿼리가 얼마나 편리한지 알 수 있어요.

기존 검색 방법은 우리가 `'elice'`의 급여가 `2500`이라는 정확한 숫자를 알고 있을 때만 사용할 수 있습니다. 즉, 미리 그 값을 알아내야 하는 수고가 필요하죠.

하지만 서브쿼리를 사용한 예시를 보세요. `(SELECT 급여 FROM employee WHERE 이름 = 'elice')` 이 부분이 바로 서브쿼리입니다. 우리는 `'elice'`의 급여가 얼마인지 미리 알 필요 없이 쿼리에게 **"`elice`의 급여를 찾아서 그 값보다 높은 급여를 받는 사원을 찾아줘"** 라고 지시할 수 있습니다. 서브쿼리가 자동으로 `'elice'`의 급여를 찾아내 메인 쿼리에 전달해주므로 훨씬 유연하게 데이터를 검색할 수 있게 되는 거죠.

---

### 서브쿼리 사용 시 주의사항

- **서브쿼리는 괄호와 함께 사용**되어야 합니다.
- **서브쿼리 안에서 `ORDER BY` 절은 사용할 수 없습니다.**
- **서브쿼리는 연산자의 오른쪽에 사용**되어야 합니다.
- **서브쿼리는 오로지 `SELECT` 문으로만 작성**할 수 있습니다.

### 🔍쉬운설명

서브쿼리를 사용할 때 꼭 지켜야 할 몇 가지 규칙들이 있습니다.

**괄호는 필수!** 서브쿼리는 마치 하나의 값처럼 취급되기 때문에 항상 `()` 괄호로 감싸줘야 합니다. 마치 수학 계산에서 괄호를 쓰는 것과 같아요. `2 * (3 + 4)`처럼요.

**`ORDER BY`는 안 돼요!** 서브쿼리 자체는 메인 쿼리에 값을 전달하는 역할만 하므로, 서브쿼리 안에서 데이터를 정렬하는 `ORDER BY` 절은 사용할 수 없습니다. 정렬은 메인 쿼리에서 해야 해요.

**항상 연산자의 오른쪽에!** 서브쿼리는 비교 연산자(`=`, `>`, `<` 등)의 오른쪽에 위치해야 합니다. `A > B`에서 `B` 자리에 서브쿼리가 들어가는 식이죠.

**`SELECT`문만 사용!** 서브쿼리는 `SELECT` 문으로만 작성되어야 합니다. 데이터를 `INSERT`하거나 `UPDATE`, `DELETE`하는 쿼리는 서브쿼리로 사용할 수 없습니다.

이 규칙들을 지켜야 SQL 오류 없이 서브쿼리를 잘 활용할 수 있습니다.

## 02. 반환에 따른 분류

### 단일 행 서브쿼리 정의

**단일 행 서브쿼리는 서브쿼리 실행 결과가 1개의 행만 나오는 서브쿼리**입니다. 서브쿼리가 한 개의 값만 반환하고, 이 결과를 메인 쿼리로 전달합니다.

### 🔍쉬운설명

단일 행 서브쿼리는 말 그대로 서브쿼리가 실행되었을 때 **결과값이 딱 한 개만 나오는 경우**를 의미합니다. 예를 들어 "사원번호 1번 직원의 급여는 얼마인가?"라는 서브쿼리를 실행하면 급여가 단 한 개의 숫자(값)로 나오겠죠? 이렇게 한 개의 값만 반환하기 때문에 메인 쿼리에서는 이 값을 **일반적인 비교 연산자(`=`, `>`, `<` 등)** 와 함께 사용할 수 있습니다.

**단일 행 서브쿼리 기본 문법:**

```sql
SELECT * FROM employee
WHERE 급여 > (SELECT 급여 FROM employee WHERE 사원번호 = 1);
```
설명: 사원번호는 기본적으로 1개만 있으므로, 서브쿼리가 한 개의 행(값)만 반환하여 단일 행 서브쿼리가 됩니다.

**단일 행 서브쿼리 연산자:**

| 기호 | 뜻 |
|------|----|
| `=` | 같다 |
| `<>` | 같지 않다 |
| `>` | 크다 |
| `>=` | 크거나 같다 |
| `<` | 작다 |
| `<=` | 작거나 같다 |

### 🔍쉬운설명

단일 행 서브쿼리에서는 서브쿼리가 하나의 값만 반환하기 때문에, 메인 쿼리에서 우리가 평소에 사용하는 **일반적인 비교 연산자들을 모두 사용**할 수 있습니다. 예를 들어, '급여가 1번 사원의 급여와 같은지', '1번 사원의 급여보다 큰지' 등을 비교할 때 위 표에 있는 연산자들을 그대로 적용하면 됩니다. 아주 직관적이죠!

---

### 다중 행 서브쿼리 정의

**다중 행 서브쿼리는 단일 행 서브쿼리와 다르게 서브쿼리 결과가 2개 이상의 행으로 반환되는 서브쿼리**입니다. 이 여러 개의 결과를 메인 쿼리로 전달합니다.

### 🔍쉬운설명

다중 행 서브쿼리는 단일 행 서브쿼리와 달리, 서브쿼리가 실행되면 **여러 개의 결과값이 쏟아져 나오는 경우**를 말해요. 예를 들어 "모든 부서에서 가장 높은 급여를 받는 사람들의 급여는 얼마인가?"라는 서브쿼리를 실행하면, 부서가 여러 개라면 여러 개의 최고 급여 값이 나오겠죠? 이렇게 여러 개의 값을 반환하기 때문에, 메인 쿼리에서는 이 여러 값들을 처리할 수 있는 **특수한 연산자(`IN`, `ANY`, `ALL`)** 들을 사용해야 합니다.

**다중 행 서브쿼리 기본 문법:**

```sql
SELECT * FROM employee
WHERE 급여 IN (SELECT max(급여) FROM employee GROUP BY 부서번호);
```
설명: 각 부서별 최대 급여를 조회하면 여러 개의 값이 반환되므로, `IN` 연산자를 사용합니다.

**다중 행 연산자:**

| 기호 | 뜻 | 사용 예시 | 설명 |
|------|----|-----------|------|
| `IN` | 하나라도 만족하면 반환 | `1 in (1, 2, 3, 4)` | 서브쿼리가 반환하는 여러 값 중 하나라도 일치하면 참(`True`)으로 판단합니다. 예시에서는 `1`이 `(1, 2, 3, 4)` 안에 있으므로 참입니다. |
| `ANY` | 하나라도 만족하면 반환, 비교연산 가능 | `10 < any (1, 2, 3, 4)` | 서브쿼리가 반환하는 여러 값 중 어떤 하나라도 조건을 만족하면 참(`True`)으로 판단합니다. 예시에서 `10`은 `1, 2, 3, 4` 중 어떤 값보다도 크지 않으므로 거짓입니다. **틀리기 쉬운 부분**: `ANY`는 '가장 작은 값보다 크면' 참입니다. `10`은 `1`보다 작지 않으므로 `< any`는 `false`. |
| `ALL` | 모두 만족하면 반환, 비교연산 가능 | `99 >= all (99, 100, 101)` | 서브쿼리가 반환하는 모든 값을 조건을 만족해야만 참(`True`)으로 판단합니다. 예시에서 `99`는 `(99, 100, 101)`의 모든 값보다 크거나 같지 않으므로 거짓입니다. **틀리기 쉬운 부분**: `ALL`은 '가장 큰 값보다 작으면' 참입니다. `99`는 `101`보다 작지 않으므로 `99 >= all`는 `false`. |

### 🔍쉬운설명

다중 행 서브쿼리가 여러 값을 반환하기 때문에, 이 값들을 메인 쿼리에서 어떻게 처리할지 정하는 특별한 연산자들이 있습니다.

**`IN`** : 가장 흔하게 쓰이는 연산자예요. "이 값들 중에 어떤 하나라도 있니?" 라고 묻는 것과 같습니다. `WHERE 급여 IN (2000, 3000, 4000)`이면 급여가 `2000, 3000, 4000` 중 하나라도 해당되면 데이터를 가져옵니다.

**`ANY`** : "이 값들 중에 어떤 하나라도 조건을 만족하니?" 라는 뜻이에요. 예를 들어 `10 < ANY (1, 2, 3, 4)`는 `10`이 `(1, 2, 3, 4)` 중 가장 작은 값인 `1`보다 큰지 묻는 것과 같아요. (여기서는 `10 < 1`이 거짓이므로 `10 < ANY (1,2,3,4)`는 거짓이 됩니다. `10`은 어떤 값보다도 작지 않기 때문입니다.) 즉, **`ANY`는 여러 값 중 하나라도 조건을 만족하면 참**이 되지만, 비교 연산자와 함께 사용할 때는 **가장 작은 값 또는 가장 큰 값과의 비교**를 염두에 두어야 합니다. 예를 들어 `급여 > ANY (2000, 3000, 4000)`은 급여가 이 값들 중 최소값(`2000`)보다 크면 참입니다.

**`ALL`** : "이 값들 모두 조건을 만족하니?" 라는 뜻입니다. `99 >= ALL (99, 100, 101)` 예시에서는 `99`가 `(99, 100, 101)`의 모든 값보다 크거나 같아야 하는데, `100`이나 `101`보다는 작죠? 그래서 거짓입니다. 즉, **`ALL`은 여러 값 중 모든 값이 포함되어 조건을 만족해야만 참**이 됩니다. 예를 들어 `WHERE 급여 > ALL (2000, 3000, 4000)`은 급여가 이 값들 중 최대값(`4000`)보다 커야만 참입니다.

**`ANY`와 `ALL`은 헷갈리기 쉬우니 예시와 함께 잘 이해해두세요!**

## 03. 위치에 따른 분류

### 일반적인 서브쿼리의 형태 (WHERE 절)

**가장 일반적인 형태의 서브쿼리로, 주로 `WHERE` 절에서 조건으로 사용**됩니다.

```sql
SELECT * FROM employee
WHERE 급여 > (SELECT 급여 FROM employee WHERE 이름 = 'elice');
```

### 🔍쉬운설명

서브쿼리는 SQL 문장 안의 다양한 위치에 올 수 있는데, 그중 **가장 흔하고 기본적인 형태가 바로 `WHERE` 절에서 조건을 설정하는 데 사용되는 것**입니다. 위 예시처럼 `WHERE` 뒤에 `(SELECT ...)` 형태로 들어가서 메인 쿼리가 데이터를 필터링하는 기준을 제공하는 역할을 합니다. 앞서 `'elice'`의 급여 예시도 바로 이 `WHERE` 절 서브쿼리에 해당됩니다.

---

### ✨ 스칼라 서브쿼리 정의

**스칼라 서브쿼리는 `SELECT` 절에서 사용하는 서브쿼리**입니다. 스칼라 서브쿼리는 **오로지 단 하나의 행만 반환**하며, 마치 `JOIN`을 사용한 것과 같은 결과를 나타냅니다.

### 🔍쉬운설명

스칼라 서브쿼리는 일반적인 서브쿼리와는 다르게 **`SELECT` 절에 직접 들어가는 쿼리**예요. 여기서 '스칼라'라는 이름은 **"하나의 값"** 을 의미합니다. 즉, 스칼라 서브쿼리는 항상 **결과값만 반환**해야 합니다. 마치 `JOIN`을 사용해서 다른 테이블의 정보를 가져오는 것처럼, 각 행에 대한 추가 정보를 `SELECT` 절에서 바로 조회할 때 유용하게 쓰입니다. 예를 들어, 학생 이름 옆에 그 학생의 평균 점수를 바로 출력하고 싶을 때 사용할 수 있습니다.

**서브쿼리 사용 방법:**

```sql
SELECT students.name, (
    SELECT math
    FROM middle_test as m
    WHERE m.student_id = students.student_id
) AS middle_avg
FROM students;
```
설명: `students` 테이블의 각 학생(`students.name`)에 대해 `middle_test` 테이블에서 해당 학생의 수학 점수(`math`)를 찾아 `middle_avg`라는 별칭으로 함께 출력합니다. 여기서 `(SELECT math ...)` 부분이 스칼라 서브쿼리이며, 각 `math` 점수만 반환합니다.

### 🔍쉬운설명

위 예시를 보면 `SELECT` 절 안에 `(SELECT math ...)` 부분이 들어가 있는 것을 볼 수 있죠? 이것이 바로 **스칼라 서브쿼리**입니다.

- **`SELECT students.name, (...) AS middle_avg`** : `students` 테이블에서 학생의 `name`을 가져오면서, 괄호 안의 서브쿼리 결과는 `middle_avg`라는 새 이름으로 함께 가져오겠다는 뜻입니다.
- **`(SELECT math FROM middle_test as m WHERE m.student_id = students.student_id)`** : 이 서브쿼리는 `student_id`와 일치하는 `middle_test` 테이블에서 각 학생의 `math`(수학 점수)를 찾아 반환합니다.

결과적으로, `students` 테이블의 모든 학생 이름 옆에 해당 학생의 중간고사 수학 점수를 함께 보여주는 결과가 나옵니다. 마치 `JOIN`을 사용해서 두 테이블의 정보를 합친 것처럼 보이는데, `SELECT` 절에서 바로 필요한 값을 가져와서 출력하는 것이죠. **이때 중요한 점은 각 학생마다 서브쿼리가 반환하는 `math` 값이 하나여야 한다**는 것입니다.
