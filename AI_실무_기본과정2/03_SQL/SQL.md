## 1[강의자료] SQL 시작하기.pdf

# 요약
이 강의는 SQL을 사용하여 데이터를 효율적으로 다루는 방법을 소개합니다. 데이터베이스의 기본 개념부터 시작하여, 테이블에서 데이터를 검색하고, 조건을 추가하여 데이터를 필터링하며, 여러 조건을 복합적으로 사용하는 방법에 대해 다룹니다.

## SQL이란?
데이터베이스는 여러 사람이 **공유**해 사용할 목적으로 **통합하여 관리**되는 데이터의 모음입니다 . Maria DB, Amazon Redshift, Oracle DB 등 다양한 종류가 있지만  , 데이터베이스의 종류와 상관없이 **검색과 분석에 사용되는 기본 방법은 동일**합니다 . SQL(Structured Query Language)은 데이터베이스에 **접근하고 조작하기 위한 표준 언어**입니다 . SQL은 데이터 검색, 삽입, 수정, 삭제, 데이터베이스 및 테이블 생성 등 다양한 작업을 수행할 수 있지만 , 이 강의에서는 주로 **데이터 검색**에 초점을 맞춥니다 .


😊 **데이터베이스 (DB)** 는 마치 거대한 도서관이나 파일 캐비닛 같아요. 여러 사람이 자료를 공유하고, 체계적으로 정리해서 관리할 수 있도록 만들어진 데이터들의 모음이죠. 🔍 우리가 흔히 듣는 Maria DB, Oracle DB, Amazon Redshift 같은 이름들은 이 도서관을 운영하는 *방식*이나 *회사*가 다르다고 생각하면 돼요.

❓ 그럼 이 많은 DB들을 다 알아야 할까요? 정답은 "아니요!"입니다.  DB마다 세부적인 사용법은 조금씩 다르지만, 데이터를 찾고(검색), 분석하는 **기본적인 방법은 거의 같아요**. 마치 모든 자동차를 운전하는 방법이 조금씩 달라도, 기본적으로 핸들, 브레이크, 가속 페달이 있는 것처럼요.

🔑 이 기본적인 방법을 알려주는 **표준 언어**가 바로 **SQL(Structured Query Language)**입니다.  SQL은 DB에 들어가서 데이터를 **찾고(검색), 넣고(삽입), 고치고(수정), 지우는(삭제)** 등의 일을 할 수 있게 해줘요.  이번 수업에서는 특히 **데이터 검색**에 집중해서 SQL이 어떻게 데이터를 찾아오는지 배워볼 거예요. 예를 들어, `DESC Employees;` 라는 쿼리(질문)는 'Employees'라는 대상에 대한 정보를 'DESC'라는 명령으로 보여달라는 의미예요. 


## 테이블에서 데이터 검색하기
데이터베이스는 주로 **관계형 데이터베이스**와 **비관계형 데이터베이스**로 나뉘며, 가장 많이 사용됩니다 . **관계형 데이터베이스**는 하나 이상의 테이블로 이루어지며, 서로 연결된 데이터를 가지고 있고, SQL을 통해 제어 가능합니다 . 테이블은 **컬럼(Column)**과 **레코드(Record)**로 구성된 표이며 , 모든 테이블은 고유의 이름으로 구분됩니다 .

### SELECT문의 기본 문법
테이블에서 데이터를 가져올 때는 `SELECT` 문을 사용합니다. 예를 들어, `book` 테이블에서 책의 제목(title)과 저자(author)를 검색하려면 다음과 같이 작성합니다  .

```sql
SELECT title, author
FROM book;
```
- `SELECT`: 검색할 컬럼 (명령)
- `FROM`: 검색할 테이블

모든 데이터를 가져오려면 `SELECT *`을 사용합니다 .
```sql
SELECT *
FROM book;
```
- `*`: 모든 컬럼을 의미

### DISTINCT를 이용한 중복 제거
`DISTINCT` 키워드를 사용하면 검색 결과에서 **중복된 값을 제거**하고 보여줍니다 .
```sql
SELECT DISTINCT title, author
FROM book;
```
`DISTINCT` 사용 시 주의할 점은, 2개 이상의 컬럼을 명시할 경우, 한 컬럼에 중복이 있어도 다른 컬럼의 값이 다르면 다르게 취급한다는 것입니다 . 즉, `title`과 `author`가 **모두** 동일한 레코드만 중복으로 간주하고 제거합니다.


🔍 우리가 도서관에서 책을 찾는 것처럼, 데이터베이스에서도 원하는 데이터를 찾아야 해요. 가장 흔히 사용되는 데이터베이스는 **관계형 데이터베이스**와 **비관계형 데이터베이스**인데, 이 강의에서는 특히 여러 표(테이블)들이 서로 연결되어 있는 **관계형 데이터베이스**에 집중할 거예요.  

📚 **테이블**은 마치 엑셀 시트처럼 생겼어요. 
- **컬럼(Column)**: 표의 맨 위 제목들, 예를 들면 '책 제목', '저자', '출판사' 같은 것들이에요. (세로 줄)
- **레코드(Record)**: 각각의 실제 데이터 한 줄 한 줄, 예를 들면 '어린왕자', '생텍쥐페리', '엘리스 출판' 이 한 묶음이 레코드예요. (가로 줄)

⭐ **데이터 검색의 기본: SELECT문** 
데이터를 가져오는 가장 기본적인 명령은 `SELECT`입니다.
- `SELECT [가져올 컬럼 이름]`
- `FROM [데이터를 가져올 테이블 이름]`

예를 들어, `book`이라는 테이블에서 `title`과 `author` 컬럼만 보고 싶으면 `SELECT title, author FROM book;` 이라고 써요. 
만약 `book` 테이블에 있는 **모든 정보**를 다 보고 싶다면, `title, author` 대신 `*` (별표)를 쓰면 돼요. `SELECT * FROM book;`  이렇게 하면 모든 컬럼의 모든 레코드를 가져옵니다.

🚫 **중복된 데이터 없애기: DISTINCT** 
가끔 데이터를 검색하다 보면 똑같은 내용이 여러 번 나오는 경우가 있어요. 예를 들어, '엘리스 출판'이라는 출판사가 여러 번 나올 수 있죠. 이럴 때 `DISTINCT` 키워드를 `SELECT` 뒤에 붙여주면 중복된 값을 한 번만 보여줘요.

⚠️ **`DISTINCT` 주의할 점!** 
`SELECT DISTINCT title, author FROM book;` 처럼 `DISTINCT` 뒤에 여러 컬럼을 쓰면, 두 컬럼의 **조합이 모두 같아야** 중복으로 보고 하나만 남겨요. 즉, '어린왕자', '생텍쥐페리'가 두 번 나오면 하나만 남기지만, '어린왕자', '생텍쥐페리'와 '어린왕자', '김철수'는 다른 데이터로 취급해서 둘 다 보여준다는 거죠.


## 조건을 추가하여 검색하기
특정 조건을 만족하는 데이터만 검색하려면 `WHERE` 절을 사용합니다 . 예를 들어, `book` 테이블에서 제목(title)이 '돈키호테'인 책을 검색하려면  :

```sql
SELECT *
FROM book
WHERE title = '돈키호테';
```
- `WHERE`: 조건을 설정하는 부분


🔍 우리가 도서관에서 '돈키호테'라는 특정 제목의 책만 찾고 싶을 때처럼, 데이터베이스에서도 **내가 원하는 특정 조건**을 만족하는 데이터만 골라낼 수 있어요. 

🚪 이럴 때 사용하는 마법의 문이 바로 **`WHERE`**입니다.  `SELECT`와 `FROM` 다음에 `WHERE`를 쓰고, 그 뒤에 **조건**을 넣어주면 돼요.

예를 들어, `book` 테이블에서 모든 정보를 가져오는데 (`SELECT *`), 그 중에서 `title` 컬럼의 값이 정확히 `'돈키호테'`인 레코드만 (`WHERE title = '돈키호테'`) 보여달라는 거죠. 
이렇게 하면 수많은 책 데이터 중에서 '돈키호테'만 쏙 뽑아볼 수 있습니다. 💡


## 여러 개의 조건을 추가하기
여러 조건을 사용하여 데이터를 검색할 때는 **비교 연산자**와 **복합 조건 연산자**, **기타 연산자**를 활용합니다   .

### 비교 연산자
| 연산자 | 연산의 예 | 의미                     |
| ------ | --------- | ------------------------ |
| `>`    | `N > 10`  | N이 10 초과              |
| `<`    | `N < 10`  | N이 10 미만              |
| `>=`   | `N >= 10` | N이 10 이상              |
| `<=`   | `N <= 10` | N이 10 이하              |
| `=`    | `N = 10`  | N이 10인 값              |
| `!=`   | `N != 10` | N이 10이 아닌 값         |

**예시**: `score` 테이블에서 국어(korean) 성적이 90점 이상인 값을 검색 .
```sql
SELECT *
FROM score
WHERE korean >= 90;
```

### 복합 조건 연산자
| 연산자  | 연산의 예   | 의미                          |
| ------- | ----------- | ----------------------------- |
| `AND`, `&&` | `A AND B`   | A 그리고 B를 모두 만족하는 값 |
| `OR`, `||`  | `A OR B`    | A 또는 B인 값                 |
| `NOT`, `!`  | `NOT A`     | A가 아닌 값                   |

**예시**: `score` 테이블에서 국어(korean) 성적이 90점 이상이거나 수학(math) 성적이 80점 초과인 값을 검색  .
```sql
SELECT *
FROM score
WHERE korean >= 90 OR math > 80;
```

### 기타 연산자
| 연산자    | 연산의 예          | 의미                           |
| --------- | ------------------ | ------------------------------ |
| `BETWEEN` | `A BETWEEN 10 AND 20` | A가 10과 20 사이에 포함된 값 |
| `IN`      | `A IN B`           | B에 A가 포함된 값              |
| `NOT IN`  | `A NOT IN B`       | B에 A가 포함되지 않은 값       |

**예시**: `score` 테이블에서 수학(math) 성적이 80점과 90점 사이인 값 검색 (80과 90 포함) .
```sql
SELECT *
FROM score
WHERE math BETWEEN 80 AND 90;
```


🚪 `WHERE` 문을 통해 조건을 추가하는 방법을 배웠는데, 이제는 **조건을 여러 개** 걸어서 더 정교하게 데이터를 찾아볼 거예요.  마치 "국어 점수가 90점 이상인 학생"을 찾거나, "국어 점수가 90점 이상이거나 수학 점수가 80점 초과인 학생"을 찾는 것처럼 말이죠. 

1.  **비교 연산자**: 
    숫자나 문자의 크기를 비교할 때 사용해요.
    -   `=` (같다)
    -   `!=` (같지 않다)
    -   `>` (크다), `<` (작다)
    -   `>=` (크거나 같다), `<=` (작거나 같다)

    예를 들어, `WHERE korean >= 90;`은 국어 점수(korean)가 90점 이상인 데이터만 가져오라는 뜻이에요. 

2.  **복합 조건 연산자 (논리 연산자)**: 
    여러 개의 조건을 한꺼번에 묶어서 사용할 때 써요.
    -   **`AND` (그리고, &&)**: 두 조건 모두 참일 때만 해당 데이터를 선택해요. ("국어도 90점 이상 *그리고* 영어도 90점 이상인 학생")
    -   **`OR` (또는, ||)**: 두 조건 중 하나라도 참이면 해당 데이터를 선택해요. ("국어가 90점 이상 *또는* 수학이 80점 초과인 학생") 
    -   **`NOT` (아니다, !)**: 조건이 거짓일 때 해당 데이터를 선택해요. ("국어 점수가 90점이 *아닌* 학생")

    예를 들어, `WHERE korean >= 90 OR math > 80;`은 국어 점수가 90점 이상이거나 수학 점수가 80점 초과인 데이터를 검색해요. 

3.  **기타 연산자**: 
    조금 더 특별한 조건 검색에 사용돼요.
    -   **`BETWEEN A AND B`**: A와 B 사이의 값을 검색해요 (A와 B를 포함).
        예: `WHERE math BETWEEN 80 AND 90;`은 수학 점수가 80점부터 90점까지인 값을 가져옵니다. 80점과 90점도 포함돼요. 
    -   **`IN (값1, 값2, ...)`**: 괄호 안의 값들 중 하나와 일치하는 데이터를 검색해요.
        예: `WHERE major IN ('컴퓨터공학', '전자공학');`은 전공이 컴퓨터공학이나 전자공학인 학생을 찾습니다.
    -   **`NOT IN (값1, 값2, ...)`**: `IN`의 반대로, 괄호 안의 값들과 일치하지 않는 데이터를 검색해요.

이 연산자들을 잘 조합하면 원하는 데이터를 아주 정확하게 찾아낼 수 있답니다! 🚀

## 2[강의자료] 데이터를 제어하는 DML (데이터 조작어).pdf

# 요약
이 자료는 SQL의 DML(데이터 조작어)을 활용하여 데이터를 검색, 정렬, 삽입, 수정, 삭제하는 방법에 대해 설명합니다.

## 데이터에서 유사한 값 찾기 
데이터를 정확히 기억하지 못할 때, **`LIKE`** 명령어를 사용하여 특정 문자가 포함된 문자열을 검색할 수 있습니다.  

`LIKE` 조건의 기본 문법은 다음과 같습니다: 
```sql
SELECT *
FROM table_name
WHERE column_name LIKE 'pattern';
```
`%`는 **여러 문자**를, `_`는 **단일 문자**를 의미하는 와일드카드입니다.   
- `WHERE title LIKE '%왕자';`: '왕자'로 끝나는 제목 검색 (예: '어린왕자')
- `WHERE title LIKE '어린%';`: '어린'으로 시작하는 제목 검색 (예: '어린왕자')
- `WHERE title LIKE '%린왕%';`: '린왕'이 포함된 제목 검색 (예: '어린왕자')


🔍 **`LIKE`**는 데이터베이스에서 원하는 정보를 **정확히 몰라도** 검색할 수 있게 해주는 마법의 도구라고 생각할 수 있어요. 예를 들어, 도서관에서 책 제목이 '어린왕자'인데 '왕자'라는 단어만 기억나더라도, `LIKE '%왕자'`를 사용하면 '어린왕자'를 찾아낼 수 있죠.

여기서 핵심은 **와일드카드 문자**예요.
- **`%` (퍼센트)**: 🚗 이 문자는 **0개 이상의 어떤 문자**라도 대신할 수 있어요. 마치 "어떤 글자가 와도 돼!" 하고 프리패스를 주는 것과 같아요.
  - `LIKE '%왕자'`는 "앞에 어떤 글자가 오든 상관없이 '왕자'로 끝나는 것"을 의미해요.
  - `LIKE '어린%'`는 "'어린'으로 시작하고 뒤에 어떤 글자가 오든 상관없는 것"을 의미해요.
  - `LIKE '%린왕%'`는 "어떤 글자로 시작하고 끝나든, 중간에 '린왕'이 들어있는 것"을 의미해요.
- **`_` (언더바)**: 🧍 이 문자는 **단 하나의 어떤 문자**를 대신해요. 딱 한 글자만 비워두고 찾는다고 생각하면 돼요. (슬라이드에는 없지만 중요한 개념이에요!)
  - `LIKE '데이터_베이스'`는 '데이터베이스' (한 글자)를 찾을 수 있고, '데이터 베이스' (공백 한 글자)도 찾을 수 있어요.

**언제 사용할까요?**
- 🙋‍♀️ 고객 이름 일부만 기억날 때
- 📚 책 제목이나 기사 제목의 키워드만 알 때
- 📧 이메일 주소의 특정 도메인을 찾을 때

**주의할 점:**
`LIKE` 검색은 `=` 검색보다 **느릴 수 있어요**. 왜냐하면 데이터베이스가 모든 문자열을 하나하나 비교해야 하기 때문이죠. 그래서 너무 광범위하게 `LIKE '%%'` 같은 조건을 사용하면 성능에 문제가 생길 수 있으니 주의해야 해요. 😊


## 데이터 정렬하기 
데이터를 특정 기준에 따라 정렬하고 싶을 때 **`ORDER BY`** 명령어를 사용합니다.  

`ORDER BY` 문의 기본 문법은 다음과 같습니다: 
```sql
SELECT *
FROM table_name
ORDER BY column_name [ASC | DESC];
```
- **`ASC`**: 오름차순 (작은 값부터 큰 값 순서) 
- **`DESC`**: 내림차순 (큰 값부터 작은 값 순서)  
- `ORDER BY math DESC;`: `score` 테이블에서 수학(math) 점수가 높은 데이터부터 정렬하여 검색합니다. 
- `ORDER BY math ASC;`: `score` 테이블에서 수학(math) 점수가 낮은 데이터부터 정렬하여 검색합니다. 
*참고: 1강에서 배운 `DESC 테이블명`과 기능이 다릅니다. 


🔍 **`ORDER BY`**는 마치 성적표를 등수대로 정리하거나, 사전에서 단어를 가나다순으로 배열하는 것과 같아요.  데이터를 볼 때 원하는 순서로 깔끔하게 정리해주는 역할을 하죠.

**어떤 기준으로 정렬할까요?**
- **`ASC` (Ascending, 오름차순)**: 📈 작은 값에서 큰 값으로, 또는 '가'에서 '하' 순서로 정렬해요. 기본값이라 생략해도 오름차순으로 정렬됩니다.
  - 예: `ORDER BY price ASC;` (가격이 낮은 상품부터 나열)
- **`DESC` (Descending, 내림차순)**: 📉 큰 값에서 작은 값으로, 또는 '하'에서 '가' 순서로 정렬해요.
  - 예: `ORDER BY sales DESC;` (판매량이 높은 상품부터 나열)

**다양한 활용:**
- **여러 기준으로 정렬**: `ORDER BY column1 DESC, column2 ASC;` 이렇게 여러 컬럼을 지정하면, 첫 번째 컬럼으로 정렬한 후, 같은 값을 가진 행들은 두 번째 컬럼 기준으로 다시 정렬해요. 예를 들어, 수학 점수가 같은 학생들끼리는 영어 점수 순으로 정렬하는 식이죠.
- **`LIMIT`와 함께 사용**: `SELECT * FROM students ORDER BY math DESC LIMIT 5;` 처럼 사용하면, 수학 점수가 가장 높은 상위 5명의 학생만 볼 수 있어요.  엘리스 토끼 선생님이 수학 점수가 높은 학생 5명을 찾는 예시처럼요!

**헷갈리기 쉬운 점:**
1강에서 배운 `DESC 테이블명;`은 테이블의 구조(컬럼 정보 등)를 보여주는 명령어이고, `ORDER BY column_name DESC;`는 **검색된 데이터를 내림차순으로 정렬**하는 명령어예요. 이름은 비슷하지만 하는 역할이 완전히 다르니 꼭 구분해서 기억해야 해요! 😊


## 테이블에 데이터 삽입하기 
관계형 데이터베이스의 테이블에 새로운 값을 저장할 때 **`INSERT`** 명령어를 사용합니다.  

`INSERT` 문의 기본 문법은 다음과 같습니다: 
```sql
INSERT INTO table_name (column1, column2, ...)
VALUES (value1, value2, ...);
```
- `INSERT INTO book(id, title, author, publisher) VALUES('3', '햄릿', '윌리엄 셰익스피어', '엘리스 출판');`: `book` 테이블에 '햄릿' 책 데이터를 추가합니다. 
- **TIP**: 컬럼을 명시하지 않으면 `VALUES`에 명시된 값이 테이블 생성 시 정의된 컬럼 순서대로 삽입됩니다. 


🔍 **`INSERT`**는 데이터베이스라는 창고에 **새로운 물건을 집어넣는 행위**와 같아요.  도서관에 새로운 책이 들어오면 책장에 꽂는 것과 같은 이치죠!

**핵심 구문:**
- **`INSERT INTO table_name`**: "어떤 테이블(책장)에 넣을 거야!"라고 선언하는 부분이에요.
- **`(column1, column2, ...)`**: "이 컬럼들(책장의 특정 칸)에 값을 넣을 거야!"라고 명시하는 부분이에요. 예를 들어 `(id, title, author, publisher)`처럼요.
- **`VALUES (value1, value2, ...)`**: "실제로 넣을 값들은 이거야!"라고 지정하는 부분이에요. 각 값은 위에서 명시한 컬럼 순서와 일치해야 해요.

**간편한 팁:**
만약 모든 컬럼에 값을 순서대로 넣을 예정이라면, 컬럼 이름을 굳이 명시하지 않아도 돼요.
```sql
INSERT INTO book VALUES ('3', '햄릿', '윌리엄 셰익스피어', '엘리스 출판');
```
하지만 이 경우, **테이블 생성 시 정의된 컬럼 순서와 정확히 일치하는 순서**로 값을 넣어줘야 해요. 만약 순서가 바뀌거나 빠진 컬럼이 있다면 오류가 발생하거나 잘못된 데이터가 들어갈 수 있으니 주의해야 합니다. 😲

**주의할 점:**
- **데이터 타입 일치**: 넣으려는 값의 데이터 타입(숫자, 문자열 등)이 해당 컬럼의 데이터 타입과 일치해야 해요. 문자열은 작은따옴표(`'`)로 감싸줘야 합니다.
- **제약 조건**: 테이블에 설정된 기본 키(Primary Key)나 고유(Unique) 제약 조건 등을 위반하는 값을 넣으려고 하면 오류가 발생할 수 있어요. 예를 들어, `id`가 기본 키인데 이미 존재하는 `id` 값을 또 넣으려고 하면 안 되겠죠?


## 테이블의 데이터 수정하기 
관계형 데이터베이스의 테이블에서 이미 저장된 값을 수정할 때 **`UPDATE`** 명령어를 사용합니다.  

`UPDATE` 문의 기본 문법은 다음과 같습니다: 
```sql
UPDATE table_name
SET column1 = new_value1, column2 = new_value2, ...
WHERE condition;
```
- `UPDATE book SET title = '돈키호테 1' WHERE title = '돈키호테';`: `book` 테이블에서 제목(title)이 '돈키호테'인 데이터의 제목을 '돈키호테 1'로 변경합니다. 


🔍 **`UPDATE`**는 데이터베이스 창고에 있는 물건의 **정보를 변경하는 행위**와 같아요.  책 제목에 오타가 있거나, 가격이 변동되었을 때 해당 정보를 올바르게 고치는 것과 같죠!

**핵심 구문:**
- **`UPDATE table_name`**: "어떤 테이블(책장)의 데이터를 수정할 거야!"라고 선언하는 부분이에요.
- **`SET column1 = new_value1, ...`**: "이 컬럼(특정 칸)의 값을 이렇게 바꿀 거야!"라고 실제 변경할 내용을 지정하는 부분이에요.
- **`WHERE condition`**: ⚠️ **가장 중요한 부분!** "어떤 조건에 맞는 데이터만 수정할 거야!"라고 명시하는 부분이에요. 이 조건이 없으면 **테이블의 모든 데이터가 한 번에 변경될 수 있으니** 아주 조심해야 합니다! 

**예시를 통한 이해:**
도서관에서 '돈키호테'라는 책 제목이 다른 저자의 책과 헷갈려서 '돈키호테 1'로 수정해야 할 때 :
`UPDATE book SET title = '돈키호테 1' WHERE title = '돈키호테';`
이 쿼리는 `book` 테이블에서 `title`이 '돈키호테'인 **모든 행**을 찾아서 그 `title`을 '돈키호테 1'로 바꿔줍니다. 만약 `WHERE` 조건 없이 `UPDATE book SET title = '새로운 제목';` 이라고만 했다면, `book` 테이블의 모든 책 제목이 '새로운 제목'으로 바뀌어 버리는 대참사가 발생할 거예요! 😱

**주의할 점:**
- `WHERE` 절을 **절대 잊지 마세요!** `UPDATE`와 `DELETE` 명령어는 `WHERE` 절이 없으면 테이블의 모든 행에 영향을 미치므로 매우 위험합니다. 항상 먼저 `SELECT` 문으로 변경하려는 데이터를 확인한 후 `UPDATE` 문을 실행하는 습관을 들이세요.
- 변경할 값의 데이터 타입이 컬럼의 데이터 타입과 일치해야 해요.


## 테이블의 데이터 삭제하기 
관계형 데이터베이스의 테이블에서 이미 저장된 값을 삭제할 때 **`DELETE`** 명령어를 사용합니다.  

`DELETE` 문의 기본 문법은 다음과 같습니다: 
```sql
DELETE FROM table_name
WHERE condition;
```
- `DELETE FROM book WHERE title = '돈키호테 1';`: `book` 테이블에서 제목(title)이 '돈키호테 1'인 책 데이터를 삭제합니다. 
- **Tip**: `WHERE` 조건이 없을 시 **모든 데이터가 삭제**됩니다. 


🔍 **`DELETE`**는 데이터베이스 창고에 있는 **물건을 버리는 행위**와 같아요.  잘못된 정보가 입력된 책을 책장에서 빼버리는 것과 같죠!

**핵심 구문:**
- **`DELETE FROM table_name`**: "어떤 테이블(책장)에서 데이터를 삭제할 거야!"라고 선언하는 부분이에요.
- **`WHERE condition`**: ⚠️ **가장 중요한 부분!** "어떤 조건에 맞는 데이터만 삭제할 거야!"라고 명시하는 부분이에요. 이 조건이 없으면 **테이블의 모든 데이터가 한 번에 삭제될 수 있으니** `UPDATE`와 마찬가지로 아주 조심해야 합니다! 

**예시를 통한 이해:**
잘못 입력된 '돈키호테 1'이라는 책 데이터를 삭제해야 할 때 :
`DELETE FROM book WHERE title = '돈키호테 1';`
이 쿼리는 `book` 테이블에서 `title`이 '돈키호테 1'인 **모든 행**을 찾아서 삭제합니다. 만약 `WHERE` 조건 없이 `DELETE FROM book;` 이라고만 했다면, `book` 테이블의 **모든 데이터가 사라지는** 끔찍한 일이 벌어질 거예요! 😱 (이것을 **TRUNCATE**와 혼동하기도 하는데, `DELETE`는 트랜잭션 로그를 남겨 롤백이 가능하지만, `TRUNCATE`는 훨씬 빠르고 롤백이 불가능하다는 차이가 있어요.)

**주의할 점:**
- `WHERE` 절을 **절대 잊지 마세요!** `DELETE`는 `UPDATE`보다 훨씬 더 치명적일 수 있습니다. 삭제된 데이터는 복구하기 어렵거나 불가능할 수 있기 때문에 항상 `DELETE` 쿼리를 실행하기 전에 `SELECT` 문으로 삭제될 대상을 정확히 확인하는 습관을 들여야 합니다.
- 실제 서비스 환경에서는 `DELETE` 명령어를 사용하기 전에 반드시 백업을 하거나, 트랜잭션 내에서 실행하여 문제가 생길 경우 롤백할 수 있도록 준비해야 합니다.
